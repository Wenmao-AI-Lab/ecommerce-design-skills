# 营销图形母版与多尺寸套件

> 交两样东西：像真的一样的成品平面稿，和一个改内容就能重出全套的母版文件夹——系列只变内容不变容器。

## 这个技能能做什么

**这是本包里「交付物形态」最重的一个技能**：它一次交两样东西。

**① 成品平面稿**：每个触点、每个尺寸一张最终像素，**像真实发布的海报**——不打水印、不标「示意」、不用占位。
**② 母版文件夹**：HTML/CSS 画板母版 + 内容插槽 + 素材层 + 色与字规范 + 一条命令重出全部成品的导出脚本 + README。
**成品给人看效果做决定，母版让人能改内容接着出。**

**入口 gate：三条同时成立才属于它**（`## 0. 入口 gate` 原文）：

1. 输出是**定尺寸单帧静态平面文件**（PNG/JPG/PDF，**不可滚动、不可交互、不分页**）
2. **一帧承载全部信息、一次扫读完**
3. 用途是**传播**

任何一条不成立，它会写一行「不属 create-marketing-graphics，改按 <某技能>」**明确转出**。转出目标包括：PPT/报告/手册/杂志/学术海报等**多页物** → `design-editorial-and-presentations`；**logo/VI/名片/品牌手册** → `design-brand-identities`；**网页/落地页/dashboard 等可交互界面** → `build-polished-visual-frontends`；**数据图表与重信息图** → `create-data-visualizations`；**单张无文字插画** → `create-illustrations-and-scenes`；**单个图标** → `design-icons-and-symbols`。

> ⚠️ **这些转出目标技能本包都没有提供。** 所以在本包里它只承担「海报 / 营销图形」这一档，其它档位的任务需要另找技能。**这条边界必须让买家知道。**

**五个原则（原文）：**

1. **分层版面是基底** —— 任何海报都是五层：画板 → 背景层 → 主视觉层 → 图形元素层 → 文字与品牌层。**基底是固定尺寸的 HTML/CSS 画板，不是一张生成图**；版面与全部活字只在 HTML 画板里排。每张成品的主视觉或场景级背景**必须是位图**（纯排版方向也不例外，它的背景层是有构图、光源与景深的场景级生成图）。**无缝材质、纸纹、噪点不算生成层。**
2. **一个焦点、一个主视觉、一种做法** —— 主视觉只有一个，只用一种做法（照片 / 抠图 / 插画 / 3D 渲染 / 纯排版），**不叠加第二种**；标题是唯一的第一眼。手绘几何、线描图标、「抽象形态」**不是主视觉做法**。
3. **活字不画字** —— 标题、副标、日期地点、价格、CTA、logo **全部是真实字体的活字或矢量**；生图只出背景与主视觉素材，**prompt 里明确不要文字**。
4. **系列只变内容不变容器** —— 画板、背景做法、图形元素、标题位置、信息层位置、logo 位置是**不变项**；变的只有主视觉内容与文案。
5. **像真的一样** —— 真名称、真日期、真地点、真价格、真 logo；场景可信、拼写正确；**缩小到拇指大仍能认出**。用户没给的事实用可信替身做到最终效果，并在 README 的《替换清单》逐项列出；**成品画面上永远不出现「待替换 / 待填 / 预留」**。

**七条判据 P1-P7（后文以代号引用）：**

| 代号 | 判据 |
|---|---|
| **P1 唯一焦点** | 标题或主视觉之一是第一眼，其余都退后；**缩到 200 px 高仍先看到它** |
| **P2 三级层级** | 钩子（标题/主视觉）→ 支撑（副标、日期地点）→ 细则（票价、二维码、赞助、法务）；**信息层默认集中在底部约 1/5** |
| **P3 一个主视觉一种做法** | 满版照片 / 抠图 / 插画 / 3D 渲染 / 纯排版**只选一种**；主视觉不是手绘几何 |
| **P4 活字正确** | 所有文字逐字正确、字体是所选字体、字号符合观看距离；**画面里没有生成的伪文字** |
| **P5 系列同容器** | 并排缩略像一套；**不变项逐张 diff 为零**；变量只在主视觉与文案 |
| **P6 尺寸即规格** | **每个触点用它真实的像素或毫米尺寸出图**，安全区内有标题与 CTA，**不是同一张图缩放** |
| **P7 像真的** | 没读过任务的人把它当成真实发布的海报；真 logo、真信息、可信场景，没有模板占位感 |

**交付档位（五档，先选档再动手）**：`single` 单张 · `series` 系列 · `social_kit` 社媒套件 · `display_set` 展示物组 · `campaign_full` 全案
**表达强度（三档）**：`quiet` 安静 · `editorial` 编辑感 · `loud` 张扬

## 什么时候用它

- 要做**一整个系列**的活动图，只换文案不换版式
- 交付给**客户**时需要一个能自行改内容重出图的**母版包**
- 同一活动要出货给**公众号头图、朋友圈、灯箱、易拉宝**多个幅面
- 要做**定尺寸、一次扫读完、用于传播**的单帧平面稿（海报 / KV / 传单 / 展板 / 节日贺图 / 视频封面）

**先过入口三判据**：定尺寸单帧静态？（不是 → 转出）· 一帧承载全部信息？· 用途是传播？
**任何一条不成立，本技能不接**，它会明确告诉你去用哪个技能。

**同包内怎么选**：
- 只要 **Banner / 封面 / 头图**，要多方向比稿 → 「Banner 与社媒配图设计」
- 要**整套品牌物料**（含 Logo 与 CIP） → 「全案设计流程」
- 要做 **PPT / 报告 / 手册 / 杂志**（多页物） → **本技能不接**，且本包未提供对应的转出技能

## 操作步骤

### 第 1 步：过入口 gate

对照三条判据。**三条同时成立才继续**；任何一条不成立，它会在回复里写一行「不属 create-marketing-graphics，改按 <技能名>」并转出。

### 第 2 步：读懂任务，先填决策卡

**第零步：把触点翻译成档位**（SKILL.md 标注「选技术前必做，不许跳过」）。要填的字段（原文骨架）：

```
主体: 品牌 / 活动 / 产品的正式名称，用户提供的 logo 与既有资产
唯一承诺: 这张海报只说的那一句话（一句，不是三句）
受众与场景: 谁、在哪、停留多久、离多远看
            （地铁通道 3s / 社媒信息流 1s / 展位 10s / 街头 5m）
信息层内容: 日期 / 时间 / 地点 / 票价 / 二维码或 URL / CTA 动词 /
            主办与赞助（逐条原文，缺的标"未提供"）
用户列出的触点: 逐条原文
交付档位: single | series | social_kit | display_set | campaign_full
尺寸清单: 每个触点的像素或毫米尺寸与来源
表达强度: quiet | editorial | loud
主视觉来源: route（truth_asset | generated_visual）+ 一句艺术指导
背景来源: route + 与主视觉的关系 + 一句
硬约束: 用户禁忌、既有品牌资产、语言、接收方
未知与阻断: 日期未定阻断什么、logo 缺失阻断什么
```

**还有一道「标杆索引 gate」**：要为每条「从真实平面稿里看到的规律」记一条溯源记录——`fact_id`（如 R1）· `source_frame`（哪张图哪一格）· `observed_relation`（看到的结构关系）· `protected_axis`（迁移时不能动的轴）· `target_object`（本任务里承接它的对象）· `representative_frame_evidence` · `final_frame_evidence` · `deviation_constraint`（允许偏离到哪里为止）。**技能内自带 14 张真实平面稿作标杆**（见下面「你会拿到什么」）。

### 第 3 步：写「最小系统合同」

```
画板: 触点 → 像素或毫米尺寸 → 出血 → 安全区（逐个触点）
背景层: 默认由生图产（满版场景/环境/材质），为主视觉服务
主视觉: 做法只选一种；主体是什么、占画面多大、在哪
图形元素: 系列识别用的固定形状（色块/椭圆/波纹/徽章/边框）；没有去处不建
标题: 字面、字重、字号相对画板高度的比例（1/4–1/3）、位置
文字层级: 标题 : 副标 : 信息层 : 细则 的字号比（如 100 : 45 : 22 : 14）
信息层: 内容清单、位置（默认底部约 1/5）、有无 CTA 按钮/二维码
色: 主色 1（HEX、职责）；强调色 1；中性色 ≤ 2；深浅两种底上的文字色
系列规则: 不变项清单；可变项清单；变量来源（data.json 字段）
世界设定: 生成素材共用的场所、时段、光线、人群
```

### 第 4 步：先做「定调帧」

**先完成决定成败的那一帧**，而不是把十个尺寸一起开工。定调帧定下来，后面才是铺开。

### 第 5 步：从定调帧铺开系列、套件与母版

### 第 6 步：自检（七条判据逐条过）

```
→ 缩到 200 px 高，第一眼是不是标题或主视觉（P1）
→ 三级层级是否成立，信息层是否集中组织，日期/地点/行动入口是否容易定位（P2）
→ 主视觉是否只有一个、只用一种做法（P3）
→ 逐字校对全部文字，字号是否符合观看距离（P4）
→ 尺寸与安全区是否等于规格（P6）
→ 与两张真实同类海报缩略并排，能否一眼分出是谁
```

## 命令速查

**没有命令行。**它是纯对话型技能，靠结构化输入（决策卡、最小系统合同、溯源记录）驱动。

| 它会在这些时候让你停手 || 为什么 |
|---|---|
| 第 6 节「看见这些迹象就停下来重构」 | 有明确的重构信号清单，触发就回退 |
| 第 7 节「按风险检查，不制造审查循环」 | 按风险定检查强度，**不为了让流程好看反复返工** |

**交付物清单登记格式（SKILL.md 原文）**：每条记 `path` / 类型（成品｜母版｜素材）/ 触点与尺寸 / 生成方式与参考图 / 状态（`planned → built → verified`）/ 证据。

**素材来源纪律**：字体、图像、商标与生成资产**都要记录来源、许可与替换边界**。

## 完整对话案例

### 本包实测：这个技能在本包里没被调用，但它自带的东西很有价值

**如实说**：本包的全流程实测（轻奢陶瓷马克杯）**没有调用这个技能**。本包的海报与主图走的是自建 HTML 画板 + 公共运行库 `render_card.py` 渲染的路线。

**原因**：本技能的第 1 条原则要求「**每张成品的主视觉或场景级背景必须是位图（生图产出）**」，而本包里**没有 `image_generate` 这套生图工具链**（SKILL.md 里明确要调用它）。在缺少生图能力时，这条原则无法满足，所以本包没有用它。**这是能力边界，不是技能缺陷**——说明书把这条写明，买家才能判断自己的环境能不能用。

**但它有两样东西，本包在实际工作里用得上，且可验证：**

**① 它的「活字不画字」纪律，与 AI 出图的中文乱码风险正好对治。**本包实测中确实踩过这条：AI 生成的中文/服饰类图片文字是乱码，所以本包的做法是**AI 只出无字底图，文字全部用 HTML/SVG 层叠加**（交付物 `_tmp/` 下的 HTML 画板与 `_tmp/assets/` 下的无字底图就是这个分工）。这正是本技能第 3 条原则的原话：「生图只出背景与主视觉素材，**prompt 里明确不要文字**」。

**② 它的 P1「缩到 200 px 高仍先看到它」是可执行的量化判据，本包用等价口径执行了。**本包落成的对应口径是「**净版特写的取景框与锐度预算：显示高 ÷ 源长边 ≤ 1.35×**」——也就是**缩得越小越要保证主体还没糊掉**。这句话和 P1 说的是同一件事。

**它唯一留下的实测证据，是交付物里那份《本轮修正记录》的写法。**本包交付物的 `07_过程档案/08_本轮修正记录.txt` 开头写着：

> 本文件只记录真被抓出来、真修掉的问题。数字全部由脚本回读磁盘得到，**不抄上一版记录，也不四舍五入到好看**。

这正好对应本技能第 5 条原则「**像真的一样**」的底层态度：**成品不能有占位感，过程记录也不能有美化感**。

## 常见问题 FAQ

**Q1：我只有一张图要做，也需要母版文件夹吗？**
A：需要。SKILL.md 的交付定义就是两样东西：**成品给人看效果，母版让人能改内容接着出**。哪怕这次只出一张，母版也是交付物的一部分。

**Q2：`image_generate` 是什么？我没有怎么办？**
A：它是 SKILL.md 里调用的生图能力。**本包没有提供这套工具链。**技能的第 1 条原则要求主视觉/背景必须是位图产出，所以**没有生图能力时本技能的核心流程跑不完整**——这种情况建议把任务交给有生图能力的流程，或改用纯 CSS + 实拍素材的路线（但那样就不完全符合它的第 1 条原则了）。

**Q3：我想做 PPT / 报告 / 手册，能用它吗？**
A：**不能。**入口三判据第 1 条就要求「定尺寸单帧静态平面文件，**不分页**」。多页物它会明确转出到 `design-editorial-and-presentations`——**而那个技能本包没有提供**，所以要另找方案。

**Q4：系列图怎么保证看起来是一套？**
A：靠 P5「**不变项逐张 diff 为零**」。画板、背景做法、图形元素、标题位置、信息层位置、logo 位置是不变项；变的只有主视觉内容与文案。**验收方式是并排缩略看像不像一套。**

**Q5：成品上能写「此处替换 logo」吗？**
A：**绝对不能。**SKILL.md 原话：「成品画面上**永远不出现「待替换 / 待填 / 预留」**」。用户没给的事实要用**可信替身**做到最终效果，然后在 README 的《替换清单》里逐项列出。

**Q6：主视觉能用「手绘几何 / 抽象形态」吗？**
A：不能。第 2 条原则明确写：**手绘几何、线描图标、「抽象形态」不是主视觉做法**。做法只有五种：满版照片 / 抠图主体 / 插画 / 3D 渲染 / 纯排版。

**Q7：背景层能直接用一个纯色吗？**
A：默认不行。背景层**默认由生图产出**（满版场景 / 环境 / 材质）；**纯色只是例外，且必须从主视觉取色**，并要写清它和主视觉的关系。SKILL.md 原话：「"默认暖白纸"不是合法取值」。

**Q8：`references/poster-examples/` 里的图我能直接用吗？**
A：**不能直接当素材用。**它们是**参考标杆**（`manifest.json` 写明是「真实平面稿、2025–26」，用于提炼结构规律）。商用前请自行确认各案例的授权范围。

**Q9：它能做印刷吗？**
A：能。`display_set` 与 `campaign_full` 档位覆盖展示物与户外幅面，尺寸清单按**真实的像素或毫米尺寸**逐个出（P6）。但它是「示例与方向」，不是印刷厂文件——SKILL.md 原话：「我们做的是示例与方向，不是印刷厂文件；**但示例必须像真的一样**」。

## 注意

- **入口三判据（必须三条同时成立）**：① 输出是定尺寸单帧静态平面文件（**不可滚动、不可交互、不分页**）② 一帧承载全部信息、一次扫读完 ③ 用途是传播。任何一条不成立，它会明确转出到对应技能——**而那些转出目标技能本包都没有提供**。
- **本技能的转出目标（本包均未提供）**：PPT/报告/手册/杂志/学术海报 → `design-editorial-and-presentations`；logo/VI/名片/品牌手册 → `design-brand-identities`；网页/落地页/dashboard → `build-polished-visual-frontends`；数据图表与重信息图 → `create-data-visualizations`；单张无文字插画 → `create-illustrations-and-scenes`；单个图标 → `design-icons-and-symbols`。
- **核心是「分层版面」**：画板 → 背景层 → 主视觉层 → 图形元素层 → 文字与品牌层。**基底是固定尺寸的 HTML/CSS 画板，不是一张生成图**；用 SVG 坐标排版面即视为基底失败。
- **主视觉/背景必须是位图产出**（纯排版方向也不例外，它的背景层必须是有构图、光源与景深的场景级生成图）。**无缝材质、纸纹、噪点不算生成层。**本包未提供 `image_generate` 工具链，这条原则在本包环境下无法满足——**如实告知，不含糊**。
- **活字不画字**：标题、副标、日期地点、价格、CTA、logo **全部是真实字体的活字或矢量**；生图只出背景与主视觉素材，**prompt 里明确不要文字**。（这条正好对治 AI 出图的中文乱码风险。）
- **一个焦点、一个主视觉、一种做法**：做法只有五种（满版照片 / 抠图主体 / 插画 / 3D 渲染 / 纯排版），**不叠加第二种**；**手绘几何、线描图标、「抽象形态」不是主视觉做法**。
- **系列只变内容不变容器**：不变项逐张 diff 为零；验收是并排缩略看像不像一套。
- **像真的一样**：成品画面上**永远不出现「待替换 / 待填 / 预留」**；没给的事实用可信替身做到最终效果，并在 README 的《替换清单》逐项列出。
- **背景层默认生图，纯色是例外且必须从主视觉取色**；SKILL.md 原话：「"默认暖白纸"不是合法取值」。
- **信息层默认集中在底部约 1/5**；P2 要求信息层集中组织，日期、地点与行动入口必须容易定位，「不能无规则散落」。
- **P6 尺寸即规格**：每个触点用**真实的像素或毫米尺寸**出图，**不是同一张图缩放**。
- **它能主动转交**：长期品牌系统转交品牌领域并继承其批准资产；编辑出版物与学术海报转交编辑领域；独立插画与数据图表转交对应领域。
- **素材来源纪律**：字体、图像、商标与生成资产**都要记录来源、许可与替换边界**，并以最终像素或等价终态验收。
- SKILL.md 结尾有「第 6 节：看见这些迹象就停下来重构」与「第 7 节：按风险检查，不制造审查循环」——**后者明确反对为了流程好看而反复返工**。
- 本技能**无 `scripts/`**（SKILL.md 里提到的脚本属于上游生态的其它技能），交付靠 HTML/CSS 画板 + 导出脚本；`agents/openai.yaml` 是上游的技能声明文件。
- 本技能没有 `EASEL-META.md`：从公共开源仓库整包收录。
