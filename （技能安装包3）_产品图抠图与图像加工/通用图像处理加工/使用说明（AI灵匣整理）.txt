# 通用图像处理加工

> 只加工已有图片，不做视觉设计——十种子命令把平台适配、体积压缩、水印联排全部钉成确定性调用。

## 这个技能能做什么

十个子命令覆盖电商出图后的全部收尾动作：

| 子命令 | 用途 |
|---|---|
| `resize` | 按宽 / 高 / 百分比缩放，`--keep-ratio` 在框内等比不拉伸 |
| `crop` | 按坐标裁，或居中裁到指定尺寸 |
| `pad` | **补边到目标比例**（社媒适配核心），不裁内容不变形 |
| `convert` | 转 png / jpg / webp |
| `compress` | 定质量，或逼近目标文件大小上限 |
| `watermark` | 文字水印（自动找系统中文字体）或图片水印 |
| `round` | 圆角，输出透明 png；`--radius-percent 50` 得圆形 |
| `collage` | 横向 / 纵向 / 网格 NxM 拼接 |
| `thumbnail` | 生成缩略图（最长边像素） |
| `info` | 读尺寸 / 格式 / 比例 / 体积 / 透明通道（JSON） |

**适配思路**：优先 `pad`（补边不裁内容、不变形）保全画面；追求满版无边则 `crop` 居中裁到目标比例；仅需缩小体积用 `resize` / `compress`。

## 什么时候用它

- 图片尺寸不符合平台要求，要批量改到规定像素
- 图体积超平台上限，要压到指定 KB
- 要把横图 / 竖图补边成 1:1 或 3:4，又不裁掉主体
- 要给一批图统一加水印
- 要把多张细节图拼成一张联排或九宫格
- 要确认某张图到底是什么尺寸、多少 KB

## 需要准备什么

| 材料 | 说明 | 必需 |
|---|---|---|
| 图片 | 一张或多张已存在的图片路径（png / jpg / webp） | 是 |
| 目标参数 | 尺寸、比例、质量、水印文字、拼接方式 | 是 |

**依赖**：只有 Pillow（`python -c "import PIL"` 能过即可），**不需要 rembg，也不需要 chromium**。脚本随「电商美工公共运行库」提供。

## 操作步骤

### 第 1 步：确认输入与目标

确认图片存在，并明确要做什么（尺寸？比例？体积？水印？）。

### 第 2 步：调子命令

社区适配推荐：需要精确 1080×1440 时，**先 `resize --width 1080` 再 `pad --ratio 3:4`**——因为 `pad` 只补边、不缩放原图像素，输出尺寸由原图推算而来。

### 第 3 步：核对回显

每条命令回显 `✅ 路径 (宽x高, 大小KB)`；`info` 输出 JSON。多步操作可串联（先 resize 再 compress）。

参考平台尺寸见 `references/platform-sizes.md`，高频速记：小红书竖版图文 **1080×1440（3:4）**、竖版海报 **1080×1920（9:16）**、朋友圈 / 通用方图 **1:1**、横版封面 **16:9**、公众号头图 **900×383**、抖音封面 **9:16**。

## 命令速查

| 命令 | 用途 |
|---|---|
| `image_ops.py resize -i 入 -o 出 --width 1080` | 按宽缩放 |
| `image_ops.py resize -i 入 -o 出 --percent 50` | 按百分比缩放 |
| `image_ops.py resize -i 入 -o 出 --width 1080 --height 1440 --keep-ratio` | 框内等比不拉伸 |
| `image_ops.py crop -i 入 -o 出 --box 100,50,900,650` | 按坐标裁 |
| `image_ops.py crop -i 入 -o 出 --width 1080 --height 1080` | 居中裁到指定尺寸 |
| `image_ops.py pad -i 入 -o 出.png --ratio 9:16 --background "#ffffff"` | 补边到目标比例 |
| `image_ops.py convert -i 入.png -o 出.webp --format webp --quality 85` | 转格式 |
| `image_ops.py compress -i 入.jpg -o 出.jpg --quality 80` | 定质量压缩 |
| `image_ops.py compress -i 入.jpg -o 出.jpg --max-kb 200` | 压到体积上限 |
| `image_ops.py watermark -i 入 -o 出.png --text "@账号名" --position bottom-right --opacity 0.5 --size 40` | 文字水印 |
| `image_ops.py watermark -i 入 -o 出.png --image logo.png --scale 0.3 --opacity 0.8` | 图片水印 |
| `image_ops.py round -i 入 -o 出.png --radius 60` | 圆角 |
| `image_ops.py round -i 头像.jpg -o 出.png --radius-percent 50` | 圆形裁切 |
| `image_ops.py collage -i a.jpg b.jpg c.jpg -o 出.jpg --mode horizontal --gap 12` | 横向拼接 |
| `image_ops.py collage -i 1.jpg 2.jpg 3.jpg 4.jpg -o 出.jpg --grid 2x2 --cell-width 540` | 网格拼接（列x行） |
| `image_ops.py thumbnail -i 入.jpg -o 出.jpg --size 256` | 缩略图 |
| `image_ops.py info -i 入.jpg` | 读图信息（JSON） |
| `image_ops.py --selftest` | 自检 |

## 你会拿到什么

- 处理后的图片文件（路径由你指定，或默认写入 `outputs/主题名/`）
- 每条命令一行回显：`✅ 路径 (宽x高, 大小KB)`
- `info` 的 JSON：尺寸 / 格式 / 比例 / 体积 / 是否含透明通道
- 可串联的多步处理链（先缩放再压缩、先圆角再拼接等）

## 完整对话案例

### 案例：一套主图适配三个平台并压到上限内

**你说：** 这 5 张主图帮我做三件事：① 补边成 1:1 给淘宝；② 补成 3:4 给小红书；③ 每张压到 200KB 以内。

**它做：**

```bash
# ① 淘宝 1:1
python ...\image_ops.py pad -i 主图\01.jpg -o outputs\屿陶\淘宝\01.png --ratio 1:1 --background "#ffffff"
# ② 小红书 3:4（先定宽再补边，尺寸才精确）
python ...\image_ops.py resize -i 主图\01.jpg -o outputs\屿陶\小红书\01.jpg --width 1080
python ...\image_ops.py pad    -i outputs\屿陶\小红书\01.jpg -o outputs\屿陶\小红书\01_3x4.jpg --ratio 3:4 --background "#ffffff"
# ③ 压体积
python ...\image_ops.py compress -i outputs\屿陶\淘宝\01.png -o outputs\屿陶\淘宝\01_200k.jpg --max-kb 200
```

**你会看到：**

```
✅ outputs\屿陶\淘宝\01.png (1259x1259, 486KB)
✅ outputs\屿陶\小红书\01.jpg (1080x1440, 268KB)
✅ outputs\屿陶\淘宝\01_200k.jpg (1259x1259, 196KB)
```

**它最后会提醒：** 你让它压的是 `.png`，但 `compress` 只能输出 jpg / webp（png 无损），所以它把输出后缀改成了 `.jpg`——这是脚本的既定行为，不是出错。

### 案例 2：九宫格细节图联排

**你说：** 把这 4 张细节图拼成 2×2 的九宫格，格间距 10，单元格统一 540×540。

**它做：**

```bash
python ...\image_ops.py collage -i d1.jpg d2.jpg d3.jpg d4.jpg -o outputs\屿陶\细节联排.jpg --grid 2x2 --gap 10 --cell-width 540 --cell-height 540
```

**它会先检查一件事：** `--grid` 是「列x行」，2x2 只能装 4 张；格子数装不下图片数会报错。单元格尺寸默认取**第一张图**的宽高——所以把最大的一张放第一个，或像上面这样显式给尺寸。

## 常见问题 FAQ

**Q1：`crop` 想放大为什么报错？**
A：居中裁剪的尺寸不许大于原图，超过直接报错退出。要放大用 `resize`。

**Q2：`pad` 出来不是我要的精确尺寸？**
A：因为 `pad` 只补边、不缩放原图像素，输出尺寸由原图推算而来。要精确 1080×1440 得先 `resize --width 1080` 再 `pad --ratio 3:4`。

**Q3：`compress --max-kb` 压不到目标怎么办？**
A：即使质量降到最低仍超上限时，脚本只 WARN 并给你最小的一张。此时先 `resize` 减像素再压。另外注意 `compress` 只能输出 jpg / webp，png 是无损的，别忘了写对输出后缀。

**Q4：`round` 输出 `.jpg` 会怎样？**
A：圆角需要透明通道，输出后缀写 `.jpg` 会被自动改成 `.png` 并提示。

**Q5：中文水印变成方框了？**
A：说明没找到系统中文字体。Windows 下正常会命中 `C:/Windows/Fonts/msyh.ttc`；找不到会降级成默认位图字体并打 WARN。用 `--font` 手动指定字体文件即可。

**Q6：透明图存成 jpg 会不会丢透明？**
A：会，脚本自动垫白底——这是预期行为。

**Q7：它能不能从文字 / 数据生成图？**
A：不能，也不该。本技能只加工已有图片；要从文字生成画面用卡片、海报、信息图技能。
