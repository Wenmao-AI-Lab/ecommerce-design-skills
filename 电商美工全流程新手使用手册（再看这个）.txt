第0章｜先搞懂这个技能包是什么
──────────────────────────────────────────────────────────

这是一套「电商美工全流程」技能包，共 14 个技能，外加 1 个必须前置安装的公共运行库，按 7 个阶段组织：

   1 公共运行库与账号视觉基线 —— 先有地基：底层脚本 + 品牌画像
   2 竞品拆解与出图提示词     —— 先看对手长什么样
   3 产品图抠图与图像加工     —— 把自己的商品图弄干净、弄成平台尺寸
   4 海报主图与信息图         —— 出竖版海报、章节卡、数据图
   5 文案策划与润色打磨       —— 写卖点、再去 AI 味
   6 详情页拼合与多图合成     —— 拼成长图和九宫格
   7 发布前质量关卡           —— 上架前最后一次把关

它的核心差异点是：

  ① 产出的是真实图片文件。抠图、改尺寸、渲染卡片、拼长图、出 GIF 都是本地脚本
     真跑出来的 JPG/PNG/GIF，不是给你一段"建议你用某某配色"的文字方案。
  ② 有一个贯穿始终的品牌画像。第 1 阶段建的 style.md 里的强调色、字体、禁区不是写完
     摆着的：实测海报、7 张详情页章节卡、详情页长图、进度环 GIF 都从这份档案取色，
     禁写项由文案红线扫描逐行兜住。边界也说清楚——主图是实拍商品图本身不吃色，
     条形竞赛 GIF 用脚本内置色盘（实测锁不住品牌色）。
  ③ 每一个技能都配了中文说明文件，看一眼就知道什么时候该用它、它会回你什么。

一句实话先说在前面：本包**没有**一个"一句话跑完全流程"的总入口技能。原包里那个
主入口实测只能产出几何色块废图（详见附录 B），已经删掉了。所以现在的全流程跑法
是按目录编号 1 → 7 的阶段顺序，把需求交给 AI，由它依次调用对应技能——第 4 章给了完整
的调用顺序和每步该看到的产物。

本包到现在跑过四轮完整实测，四轮分别回答一个问题：
  第 4 章｜首轮 —— 随机取一款真实商品（手作银饰 JS151），从建档跑到发布前质检，
         41 个执行步骤，13 个技能全覆盖，硬异常 0。回答的是「能不能跑通」。
  第 5 章｜第二轮 —— 抓一套真实竞品套图当原料，出三套候选打分选最高，再按 20 个平台
         导出 224 个文件并逐张回读核验。回答的是「够不够好，能不能不只服务淘宝」。
  第三轮（结果写在第 5 章 5-8）—— 回答「够不够清楚、够不够有设计感」：自建一条本地
         Real-ESRGAN 通道并先定死三条接入判据，配色加深到七对文字全部过 WCAG AAA，
         三套母版全部重渲重打分（A 89.9 → 94.8），20 平台 224 文件重新导出逐张回读。
  第四轮（结果写在第 5 章 5-9）—— 回答「都合规了，可就是不好看，这格谁来管」：
         用第 7 阶段新加的「审美原理与视觉评审」把整套图过 7 步协议，拆出 13 条可测
         缺陷，能量化的固化成 6 道 pass/fail 关卡，重渲重打分 A 94.8 → 95.9。
这套流水线不限平台：国内 6 个 + 海外 14 个已在第二轮实导出，同一批渲染出「带字版」
和「净版」两套母版分别对应国内与海外规则（海外三条硬规则读到官方正文，其余是常见值）。

第1章｜安装：先装公共运行库，再装技能
──────────────────────────────────────────────────────────

【第 0 步，也是最容易漏的一步】装公共运行库

  这 14 个技能里有 5 个（通用图像处理加工、商品图抠图与去背景、竖版营销海报生成、
  带货转化营销文案、数据信息图与动画图表）不自带全部代码，它们调一个公共库：

    ecom-shared-runtime.zip —— 里面 6 个脚本：
      image_ops.py      改尺寸/裁剪/补边/转格式/压缩/水印/圆角/联排
      render_card.py    HTML → PNG 渲染器（卡片、海报、章节卡都走它）
      remove_bg.py      rembg 抠图与换背景
      wordcount.py      平台字数上限校验
      output_paths.py   产物落盘路径校验
      doc_convert.py    Markdown / HTML → PDF

  解压到：  C:\Users\<你的用户名>\.qoder\shared\scripts\
  （macOS / Linux 是 ~/.qoder/shared/scripts/）

  装错的典型现象：任何一步报 ModuleNotFoundError: No module named 'image_ops'
  或者 'output_paths'。看到这个报错就是第 0 步没做。

【第 1 步】装技能本体

① 上传
   打开你平时用的 AI，把技能文件夹里的 .zip 直接拖进对话框（和发图片一样）。
   要一次装完就把 14 个 zip 一起拖进去。

② 复制下面这句话，粘贴发送

   「请解压并安装我上传的这些技能包，全部装好后告诉我
     安装结果，并说明之后怎么调用它们。」

③ 装完直接用
   AI 回复「安装完成」后，直接描述你的需求就行，也可以点名调用：
   「用 remove-bg 帮我把这张商品图抠成白底」。
   不确定装好没有，就问它一句：「你现在有哪些技能？」

【第 2 步】装 Python 依赖（只用到脚本的技能需要）

   pip install Pillow numpy matplotlib rembg playwright
   playwright install chromium

   - 抠图首次运行会联网下载约 168 MB 的 u2net 模型，属正常，不是卡住。
   - 渲染卡片/海报需要 playwright + chromium；没有 chromium 时海报出不了图。

【第 3 步】设一个工作目录变量

   set EASEL_ROOT=D:\你的电商工作目录      （Windows）
   export EASEL_ROOT=/Users/你/ecom        （macOS / Linux）

   产物统一落在 %EASEL_ROOT%\outputs\<具体主题名>\ 下面。
   主题名必须具体（如「JS151竞品拆解」），写 test、output、demo 这类泛名会被
   直接拒绝——这是刻意设计，防止你把三个月后的自己搞混。

【不限平台】
   本包不绑定任何 AI 平台或品牌：只要你的 AI 支持上传和安装技能包（Skill），
   本包即可使用。

┌──────────────────────────────────────────┐
│ 🧰 电商美工公共运行库
└──────────────────────────────────────────┘
  技能标识：ecom-shared-runtime（不是技能，是脚本库，装在 .qoder/shared/scripts/）
  它干什么：六个底层脚本，本包里所有"真的出图出文件"的动作都由它们执行。
    image_ops.py     裁剪 crop / 补边 pad / 缩放 / 转格式 / 压缩到 max-kb / 加水印 / 圆角 / 联排 / 缩略图 / 读信息
    render_card.py   把一段 HTML 用 chromium 渲染成指定尺寸的 PNG（卡片、海报、章节卡共用）
    remove_bg.py     rembg 语义分割抠图：去背景出透明 PNG、换纯色底、换图片底
    wordcount.py     按平台字数上限校验（淘宝/京东/小红书标题正文）
    output_paths.py  统一校验产物必须写到 outputs/<具体主题>/ 下，泛名直接拒
    doc_convert.py   Markdown / HTML → PDF 转换（本手册的 PDF 也是它出的）
  你什么时候用：不直接用，装好就行；报 ModuleNotFoundError 时才回来查这页。
  它怎么干：命令行调用，全部参数用绝对路径。例：
    python image_ops.py crop -i 白底.jpg -o 主图_01_800x800.jpg --width 800 --height 800
    python remove_bg.py remove -i 原图.jpg -o 抠图.png --model u2netp
    python render_card.py --html card.html --width 1080 --height 1920 -o 海报.png
  注意：
    · 没有命令行需求时让 AI 替你调，你只要给图和说清目标
    · Windows 下建议先 set PYTHONIOENCODING=utf-8，否则中文输出会乱码报错

┌──────────────────────────────────────────┐
│ 📇 品牌入驻与账号画像
└──────────────────────────────────────────┘
  技能标识：skill-brand-onboarding
  它干什么：通过结构化访谈 + 公开信息采集，给品牌建一份完整画像档案，落成
    profiles/<账号名>/ 六件套：identity.md（品牌与商品事实、可讲卖点、不可宣称）、
    style.md（色板、字体层级、构图规则、Do/Don't）、audience.md（人群）、
    platforms.md（平台与尺寸口径）、preferences.md（语气与红线）、memory.md（留空，后续回写）。
  你什么时候用：新账号第一次做图、接了个新品牌、或者发现"这批图和上一批不像一家店出的"。
  触发词："账号入驻"、"建档案"、"品牌入驻"、"从零建号"、"完善账号信息"、"新品牌要做图"
  它怎么干（五个 Phase）：
    Phase 0 问一个英文小写的画像名做目录名；已存在会先摘要问你更新还是重建

│ ✂️ 商品图抠图与去背景
└──────────────────────────────────────────┘
  技能标识：remove-bg（调公共库 remove_bg.py）
  它干什么：用 rembg 语义分割把主体从任意背景里抠出来，不用绿幕。三种输出：
    透明底 PNG / 纯色（白底）JPG / 换成另一张场景图作底。
  你什么时候用：商品原图背景脏、要做白底主图、要把商品放进场景里。
  触发词："去背景"、"抠图"、"白底图"、"换背景"、"透明底"、"抠产品"、"商品白底"
  它怎么干：
    python remove_bg.py remove -i 原图.jpg -o 抠图.png --model u2netp
    python remove_bg.py remove -i 原图.jpg -o 白底.jpg --model u2netp --bg-color white
    python remove_bg.py remove -i 原图.jpg -o 场景.png --model u2netp --bg-image 场景底图.jpg
    --model 可选 u2netp（快、约 5MB）或 u2net（细、约 168MB，边缘明显更好）
  你会拿到：
    ✅ 透明底 PNG（可直接叠到任何底色/场景）
    ✅ 白底主图 JPG（平台合规底）
    ✅ 换景合成图（商品落到真实场景里；仅限主体无孔洞且与背景高对比，见下方边界）
  实测：白底路径可用——u2netp 与 u2net 两轮跑同一张实拍银饰图，垫白底后边缘干净、
    无黑色破口，逐张读图通过。
  能力边界（实测踩到，务必看）：
    · 环形 / 有孔洞 / 拍在白色台面上的低对比商品，孔洞里的背景会被当成主体保留，
      alpha 是二值的（实测非零 8.6%~11.2%，半透明 0%）。垫白底看不出来，
      一旦 --bg-image 换场景，孔里那块白背景就露出来成白色色块，商品像浮在场景上。
      本次交付的场景图因此改用实拍原图裁切，没有采用合成图。
    · --alpha-matting 在 810×1080 实拍图上实测直接崩
      （numpy MemoryError: Unable to allocate 1.86 GiB，rc=1），要先缩到 1024 长边以内再开。
    · 换景产物必须自己目检，脚本不会报警。
  怎么喊它（直接复制这句话）：
    「用 remove-bg 把这张商品原图抠成白底主图；要换场景先告诉我这类商品换景靠不靠谱」

└──────────────────────────────────────────┘
  技能标识：infographic（调公共库 output_paths.py）
  它干什么：把数据或文字变成信息图，两种输出——静态图（AntV 风格）和动画 GIF
    （条形竞赛 bar-race、进度环 progress 等）。数据你直接喂 JSON。
  你什么时候用：详情页要放"卖点数据化"的图，或者要把竞品拆解结果变成一张会动的图。
  触发词："信息图"、"数据可视化"、"GIF 图表"、"条形竞赛"、"进度环"、"对比图"、"思维导图"
  它怎么干：
    python gif_chart.py --selftest                                  自检（确认真能出 GIF）
    python gif_chart.py bar-race --data race.json --top-n 6 \
           --width 900 --duration 4 --fps 12 -o outputs/<主题>/xx.gif
    python gif_chart.py progress  --data progress.json --style ring \
           --width 700 --duration 3 --fps 12 --title "6/6 张..." -o xx.gif
  你会拿到：
    ✅ 动画 GIF（实测 900×506 / 40 帧 160ms / 833KB，700×700 / 36 帧 80ms / 470KB）
    ✅ 静态信息图（需要 PNG 时把 GIF 首帧导出即可）
  注意：
    · bar-race 的数据长度必须 ≥ --top-n，否则画不出（真实坑，报错不直观）
    · 输出路径必须落在 outputs/<具体主题>/ 下，主题名不许用 test/output
    · 需要"一个可分享的图片 URL"时，本技能不出网络图，那是 chart-visualization 的活
    · 品牌强调色只有 progress 子命令认——写在数据 JSON 的 "color" 字段里生效；
      bar-race 实测用内置色盘轮换（#F08BB4/#9661BC/#61DDAA/#F6BD16/#5B8FF9），
      没有 --color 参数，别指望它跟你的主视觉同色
    · bar-race 的帧数与时长对不上设定：脚本按 fps×duration 生成帧并打印**生成帧数**，
      Pillow 存 GIF 时把连续重复帧合并、时长累加，所以文件里帧数更少、每帧更长。
      实测传 --fps 12 --duration 4，打印 57 帧，文件实为 40 帧 ×160ms（总长 6.4s）。
      progress 同样（打印 48 帧，文件 36 帧 ×80ms ≈ 2.9s）。要卡时长只能出完自己重采样。
  怎么喊它（直接复制这句话）：

  技能标识：text-polisher

┌──────────────────────────────────────────┐
│ 👁 审美原理与视觉评审
└──────────────────────────────────────────┘
  技能标识：aesthetic-foundations
  它干什么：把绘画 / 摄影 / 平面设计 / 东方视觉传统里的判断标准，接到你这张图上。
    上一道关卡管「能不能发」，它管「为什么这样组合好看」——分数全绿的图照样可以不好看。
  你什么时候用：图渲染出来了、尺寸对齐对比度都合规，但你就是觉得差一口气的时候。

  它怎么干（7 步，顺序就是它的关键）：
    1 三秒第一印象：眼睛先落在哪？那是不是作者想让人先看的地方
    2 眯眼测试：细节糊掉后，主块/次块/装饰三层还在吗
    3 灰度测试：转黑白层级还成立吗（颜色是装饰，明度才是骨架）
    4 留白测试：这片空是「意味」还是「没填满」
    5 裁剪测试：四边各砍 10%、20%，哪些元素砍掉主信息反而更强
    6 大师参照：Vignelli / 原研哉 / Rams / 八大山人……借判断力，不是抄风格
    7 改动清单：3–5 条「[元素] 当前 X → 改为 Y + 理由」，禁止"再干净一点"这种话
  你会拿到：一段先看后说的评审描述 + 3–5 条可直接动手的改动清单（含所依据的原则）
  实测：第四轮用它过整套图，拆出 13 条可测缺陷（产品换色 ΔE76 10.19、阴影无方向、
    底部 57px 死白带、色块压住把手、吸管穿标题、标题掉孤字、左栏 319px 空带、
    无坐标轴装饰条、要点与数字重复、场景四格同角度、净版 5 槽混 3 个色号……），
    11 条当场修掉，2 条如实留着（素材只 6 个角度、场景章没有真实环境）。
  注意：
    · 纯方法论，没有 scripts/、不渲染图片；前 6 步禁止出现像素值与 hex
    · 它不给 pass/fail 也不给分数。要进自动化必须先把判断换成可测口径——本项目换出来的
      三处是：留白测试→逐行墨量死白带关卡、第一印象+裁剪→特写取景与锐度预算、
      灰度测试→打分表的文字对比最小值
    · 评审记录要落成文件。只在对话里说过一遍的评审，等于没有评审
    · zip 里没有 EASEL-META.md（技能自带 frontmatter，没额外补一份元数据文件）

               文字是矢量所以放大不糊，照片仍受抠图原分辨率限制）→ 国内平台

               → 海外平台，也用于国内平台「首图禁文字」的那个位置

            海外 14 个 —— Walmart、Amazon、eBay、Etsy、Shopify、Poshmark、

5-6 这一轮的六条限制（不要跳过）

  1. 净版 2200 的主体仍由原图封顶。本轮母版读的素材目录是 `主体_抠图_SR/`，裁边后长边
     2519–2991 px，在 2200 画布里画到 1870 px —— 已是缩小而非放大。但那套素材本身仍是把
     裁边后只有 1259–1495 px 的原抠图经本地 Real-ESRGAN x4 补出来的（判据先定死再跑图，
     母版档产品区细节实测 +3.0%~+7.6% 才允许接入），而它是随包的可复跑脚本、不是已装技能，
     且缩到 160px 只剩 +1.4%。满足尺寸不等于满足观感，要真到 2200 的观感还得换更高原图。
  2. 产品本体上仍有 STANLEY 商标。eBay/Walmart 禁的是「后加的文字/图形」，产品自带
     logo 属另一回事，但这套产物按台账规定只能作验证样，不得上架。
  3. 国内带字版首图与「首图白底无文字」冲突。这些平台请把带字版用在第 2–5 张与详情页，
     首图位换净版 01（或 walmart/amazon 的 2200 版）。
  4. 3:4 的国内版是补白不是重排。本轮逐张量非白内容包围盒占画面高（数字同时回填在
     `平台导出说明.md` 里）：淘宝/抖音/小红书的 1200×1200 带字版 84.4–91.8%，

  5. 海外平台没有「750 宽一张详情长图」这个概念（Amazon 用 A+ 模块，eBay/Shopify/Etsy

  6. 所有参数是占位值（887ml、8h/6h 保温、73mm 口径、两年质保等），上线前整组替换。

5-8 第三轮补的两件事：清晰度与可读性（结果已进上面的成品）

  ① 配色加深到"必须被读到的字"全部过 WCAG AAA
     第二轮最差的一组文字对比只有 4.95:1（A_净白的强调色压在面板底上），
     而这一组里是价格与 CTA。第三轮把三套的次级色/强调色各加深一档，
     A 的 CTA 字色改成 #FFF9F4（不写纯白是因为它和底色同值，会让"色值有没有真落地"
     这道核验变成空门）。现在七对文字/底色的最差值是 A 7.07 / B 7.11 / C 7.18:1。
     A 从 89.9 涨到 94.8，这 4.9 分里 4.6 分来自这一步。

  ② 一条本地超分通道：判据先定死，再跑图
     网络结构用纯 torch 复现 Real-ESRGAN x4plus（16.70M 参数，权重键名与张量形状
     逐条对上，missing/unexpected 必须都为空），先过五道带真值的对照自检
     （合成斜边、真实抠图、跨瓦片接缝、色彩漂移、几何保真），再按跑图前就写死的
     三条判据验收：每张在母版档产品区增益 >1.00、任一张任一显示档位 ≥0.97、
     六张母版档中位数 ≥1.05。实测 1.030~1.076x、中位 1.059x、全档位最小 1.022x → 接入。
     不设 ECOM_CUT_DIR 就仍用原抠图，整条通道可关；裁边缓存按来源分目录，不会复用旧的低清裁块。
     它买到的：2200/2400 母版在放大区间的产品区细节 +3.0%~+7.6%。
     它买不到的：160px 缩略图口径只 +1.4%；原图本身就糊的素材救不回来。

  ③ 三套母版全部重渲、重打分、重导出
     带字版 1200/2400、净版 2200 与 1650×2200、13 章详情页，全部用新色板 + 新素材重跑。
     评分器这一轮加了"色值落地核验"：成品像素里必须真找得到新色值，找不到就拒绝出分
     （否则就是拿新配色给旧图打分，分数会虚高——这一条当场抓到过一次并 exit 2）。
     20 平台 224 文件重新导出后逐张回读：尺寸全等于配方值、单张最大 113.7 KB、
     85 张白底图四角实测均 #FFFFFF、异常 0；三套详情页长图各 13 章、自检 0 问题。


5-9 第四轮补的那件事：把「设计感不强」变成拦得住出货的关卡

  起因是一句话：全套图出来了，但设计感不强、不美观。前几轮的分数（94.8）量的是对齐、
  亮度、对比、一致性——这些全绿灯的图，照样可以不好看。本轮分三步走：

  ① 先评审再动手：用第 7 阶段的「审美原理与视觉评审」（aesthetic-foundations）把整套图
     按 7 步协议过一遍，拆出 13 条可测缺陷并逐条写成文件（不写在对话里）。
     其中 2 条本机修不了，如实留着：素材只有 6 个角度、场景章没有真实环境。
  ② 每条能量化的换成一个数：ΔE76 同色板、逐行墨量死白带、特写显示高/源长边的倍率。
  ③ 把数变成会退出的关卡：check_all.py 一条命令跑 6 道关卡，每张报告还查新鲜度
     （报告不比它测量的图旧，否则判失败）。assemble_delivery.py 与 pack_pipeline.py
     读不到判定「通过」的 关卡总表.json 就拒绝出品。
     本轮实测：色板 ΔE76 A 3.15 / B 1.15 / C 3.50（阈值 4.0）；选用套最长死白带 247px
     （阈值 250，落选 C 另有 4 张 327–484px，只记录不阻塞）；净版 5 槽 ΔE76 3.39；
     特写最大 1.24×（上限 1.35×）；详情页 13 章 0 问题；产物数量齐全。
     三套重渲重打分：A_净白 95.9（选用）/ B_暖调 82.2 / C_暗调 81.3。

  新关卡上线前先证伪，不然它和"没有关卡"等价：把倍率改成 1.60 → 必须阻断；
  删掉某个画幅的实测值 → 必须阻断；把报告时间往前挪 → 必须判「报告比证据旧」。
  三个负例全翻红，这道关卡才算真的在看东西。

  本轮抓到并修掉的四个交付缺陷（都不是美观问题，但会让交付物撒谎）：
     · 流水线 zip 的买家说明写着"已过关卡"，可 check_all.py / check_colorway.py /
       check_deadband.py 压根不在打包清单里——买家拿到包，一道关卡也跑不了。
     · 交付目录里躺着上一轮的 2 张残留（shopify/主图/shadow_04.jpg、shadow_05.jpg）。
       阴影版已从 5 张改成 3 个整件角度，脚本不再写它们，导出清单里也没有它们，
       于是没有任何关卡量过它们，而交付包是整目录拷贝。导出脚本现在每次清残留并断言
       目录干净——未经验证的产物比没有产物更危险。平台导出因此从 224 个文件变成 222 个。
     · 描述产物的文字会自己过期。收尾时发现：交付包与流水线 zip 里那份 评分表.md 是
       上一轮 12:25 生成的，写着 A 94.8 分，而 14:22 的 评分.json 已经是 95.9 分——
       同一份交付物里并存两套分数。生成器读的确实是证据，问题是没人再调用它，
       六道关卡量的是图、量不到这份 md。现在 kit.guard_docs() 两条一起查：
       文档 mtime 不得早于它引用的证据（只查数值会被"恰好相同的数"绕过），
       且证据里的每个总分必须原样出现在文档正文里（只查时间，touch 一下就过了）；
       assemble_delivery.py 与 pack_pipeline.py 都在真正动笔之前调它，不过就退出并
       打印该跑哪条生成器。手册 PDF 与 TXT 里的数字同样改成构建时从证据文件读，
       读不到直接拒绝生成。负例三条（同戳通过 / 证据变新阻断 / 文档新但数错阻断）
       的回显写在 _audit/…第四轮实测.md §7.5。
     · 写着"逐张复核"的那批审图板，复核的是上一轮的图。07_过程档案/复核图 里的 34 块板子
       生成于 02:34–03:49（第三轮那批渲染），而第四轮 13:48 之后主图、详情页、净版全部重渲过；
       打包脚本原先是 `cp(_check, 复核图, ["*.png"])` 整目录拷贝，关卡量图、guard_docs 量 md，
       都没管板子本身旧不旧。现在 make_sheets.py 先清空再重渲并写 复核清单.json
       （每张板复核了哪些源图、路径相对工程根目录），assemble_delivery.cp_review() 只认这份清单：
       没有清单 / 清单说有盘上缺 / 板子 mtime 早于它复核的任一张源图，一律拒绝出品。
       上线前证伪三次：板子 mtime 回拨一天 → 阻断并指名源图；板子改名藏起来 → 报缺板；
       删掉清单 → 报无清单；三次都只能靠重跑 make_sheets.py 恢复。板数 34 → 23
       （详情页三章一板、净版按 1:1 与 3:4 分两板），交付包因此从 393 个文件变成 383 个。

  仍然存在的盲区（别假装它不存在）：
     · 色板关卡量的是渲出来的像素，版式盖在产品上的半透明蒙版会把它骗过——B 套「杯架」章
       ΔE 只有 2.18，同一素材在 C 套是 10.13，因为暖调蒙版把整体提亮了。
       配色不一致被蒙版遮住不等于一致，只能靠素材选择纪律堵。
     · 锐度关卡拦得住"放大过头"，拦不住"角度不够"：5 个主图位实际只有 3 个整件角度，
       这个缺口只报不卡——卡住渲染不会多出一个角度，只能补拍。
     · 设计感评审的产出是判断与改动清单，最后"好不好看"仍要人逐张看；分数不是转化率。

第6章｜新手常见问题 FAQ
──────────────────────────────────────────────────────────

Q1：装完一跑就报 No module named 'image_ops' / 'output_paths'？
A：漏了第 0 步。把 ecom-shared-runtime.zip 解压到 ~/.qoder/shared/scripts/。
   这 6 个脚本是 5 个技能的公共底座，不在技能自己的目录里。

Q2：产物找不到，跑到别的地方去了？
A：产物一律落在 %EASEL_ROOT%\outputs\<具体主题名>\。没设 EASEL_ROOT 就落在
   当前工作目录下。主题名写 test / output / demo 会被拒绝，这是故意的——
   换一个和商品、和用途有关的名字。

Q3：这些技能要 API key 或者联网账号吗？
A：脚本类不需要，全部本地跑。两个例外：抠图首次运行要联网下载 u2net 模型
   （约 168MB）；渲染海报/卡片要 playwright 的 chromium。品牌入驻技能在
   Phase 1 会抓公开网页，不想联网就把资料直接贴给它。

Q4：能 AI 生图吗？给张参考图让它照画出图行不行？
A：不行。本包不含出图模型。prompt-reverse 只负责"反推出词"和"出图后复核"，
   中间那步出图要你在外部出图工具做。这也是我们删掉两个原包技能的直接原因
   （它们产出的"商品图"是几何色块，或者需要外部生图调度）。

Q5：一句话跑完全流程行不行？
A：目前不能。唯一的主入口实测是废图生成器（主图是深绿圆加一个白方块，
   详情页套了别的品类的模板文字，十项门禁还全判 APPROVE），已删。
   SKILLSMP 检索 guardrail / workflow / ecommerce-image-workflow 也没找到
   可直接替换的。照第 4 章的顺序交给 AI 逐步跑，就是现在最接近自动化的用法。

Q6：为什么同一个"主图"，我出来的主体占比和手册里的不一样？
A：主体占比这类指标必须有唯一口径。本包只认 card-design 与竞品拆解给出的指标
   定义。原包有个主图技能生成器默认 25% 左右、自检线 28%、文档写 55%~80%，
   三个数互相矛盾，用它的默认参数批量出 5 张只有 1 张能过自家自检——已删。
   要 55%~70% 的主体占比，就自己在画像 style.md 里写清并按第 4 章⑩步渲染。

Q7：图片上的文字能被合规关卡查出来吗？
A：查不出来。关卡只扫你以文本形式给它的内容。主图、详情页图上烧进去的标语
   必须把原文一起贴给它，否则等于没查。

Q8：自检/评分表能不能和文案一起给关卡？
A：不能，会假阳性。评分表里必然要写"绝对化用语""第一道门"这类词，一起扫就是
   自己抓自己。只给面向买家的那部分文字。

Q9：能不能把技能改成我自己的流程？
A：SKILL.md 是纯文本，改描述、改步骤、加你自己的色板都行。但要注意：改脚本
   参数名之前先看脚本实际接受什么（--in 和 --input 这种事在原包里就出过事故，
   文档和实现不一致是删除它的理由，不是修它的理由）。

Q10：京东和天猫的尺寸规则有专门校验吗？
A：本包不带平台规则引擎。原包的出货终检技能因为"请求 tmall/京东 规则会静默
   退回 taobao 规则、还在报告里写 taobao"被删了。第二轮实测建了一份 20 个平台的
   图片矩阵（第 5 章 5-5，随包工程里有 平台矩阵.json 与 平台导出说明.md），
   每条都标了依据等级：只有 Walmart / eBay / Poshmark 三条读到官方正文，
   6 条来自二手来源，11 条（含全部 6 个国内平台）是没核实的常见值。
   所以它只能当起点，不能当依据：上传前照自己后台再核一遍，再用 image-editing
   按尺寸硬加工、用质量关卡按你写的标准检查。

Q11：这份手册和各技能文件夹里的说明文件什么关系？
A：手册是全局导航（先看这个），说明文件是单个技能的详细用法（每个技能文件夹里
   都有一份 使用说明（AI灵匣整理）.txt）。想只用某一个技能，直接看它那份。

Q12：为什么本包只有 14 个技能，别家卖 30 个？
A：因为原包 17 个里 13 个实测有问题，全删了，只留 4 个能打的，再从公开技能市场
   补齐 9 个、第四轮补 1 个判断层技能。数量少了，但每一步都能真跑出能上架的东西。
   删掉哪些、为什么，附录 B 逐条写着。

Q13：那个 89.9 分（第三轮重渲后 94.8、第四轮修完设计缺陷后 95.9），能当我上架后转化率高的保证吗？
A：不能。那 12 项指标全部从成品像素和渲染几何量出来，量的是设计质量、可读性和
   一套图的一致性（首图中心着墨、五张同基线、缩略图还能不能看清、文字对比度、
   详情接缝断层）。转化率要线上 A/B 数据，本机没有，任何技能也没给你。
   分数能替你排除的是「主图糊成一团」「详情页像模板 PPT」这类明显会掉单的形态。

Q14：这套流水线只能服务淘宝吗？
A：不是。第二轮就是按多平台跑的：国内 6 个 + 海外 14 个平台一次导出 224 个文件
   （第四轮净版改成 3 个整件角度 + 2 个重新取景特写后是 222 个），
   并且因为 eBay/Walmart/Poshmark 的官方规则禁止主图带后加文字，同一批渲染额外
   出了一套纯白无文字的「净版」母版。限制见第 5 章 5-6 那六条，别跳过。

Q15：那本包到底有没有超分？
A：没有「超分技能」——已装的 14 个技能里一个都没有，也没为了填这个格子去装一个
   验证不了的技能。但随包的「流水线工程」里有一条本地 Real-ESRGAN 通道
   （sr_selftest / sr_upscale / sr_material 三个脚本）：先定死三条接入判据再跑图，
   六张素材母版档产品区细节实测 +3.0%~+7.6% 才允许接入，验收 json 在包里。
   三个前提要认：① 权重要自己下载（约 64MB，不随包发布）；② 纯 CPU 跑六张约一小时；
   ③ 它只在放大区间兑现，缩到 160px 缩略图只剩 +1.4%，救不了原图本身不够清。

Q16：图都合规、尺寸都对，可就是看着不好看，这套包管不管？
A：管，但只到「说清楚哪里不对 + 给出能动手的改动清单」这一步：第 7 阶段两道关卡，
   前一道查合规与完整性，后一道（审美原理与视觉评审）走 7 步协议。它不给分数、
   不替你决定取舍；要它拦住出货，得把判断换成可测口径——5-9 写了本项目换出来的六道关卡。

第7章｜进阶扩展三阶段（技能 15–22）怎么用
──────────────────────────────────────────────────────────

为什么要有这三章？前 7 个阶段解决的是「一套图怎么从零做到能上架」。当这件事已经跑顺了，

【8】品牌视觉体系构建（3 个技能）
────────────────────────────────────────

  ▸ 全案设计流程（design）
    一句话：品牌侧全案一次做完，不用每个平台重画。
    什么时候用：要 Logo 多方向方案、企业视觉规范、图标、多平台社媒图一起出。
    怎么用：说清品牌名、行业、目标人群、偏好的调性，它会先给方向再出物料。
    产物：品牌识别与规范文档、Logo 方案、图标 SVG、多平台社媒图。

  ▸ 设计令牌与组件规范（design-system）
    一句话：把「主色 #FF6B35」从口头约束变成代码里能引用的变量。
    什么时候用：多人协作、要交给开发或外包执行、需要统一间距与字阶。
    怎么用：给它品牌色和几个基准尺寸，它搭三层令牌（原始→语义→组件）+ CSS 变量。
    产物：design-tokens（CSS/JSON）、间距与字阶表、组件规格。
    实测落地：本项目把强调色写进 style.md 后由海报 / 章节卡 / 长图 / GIF 逐处读取，
    这套「令牌 → 出图」的链路和本技能是同一套思路。

  ▸ 设计咨询与风格定调（design-consultation）
    一句话：先理解产品、再看一圈同类，最后给你 2–3 个可比的方向。
    什么时候用：定不下调性、要给老板或客户一份设计系统提案。
    怎么用：回答它的问题（产品、受众、竞品、禁忌色），它会调研后给方案。
    产物：设计系统提案（美学方向 / 字体 / 色彩 / 布局 / 间距 / 动效）+ 字体配色预览。

  ▸ 营销图形母版与多尺寸套件（create-marketing-graphics）

    什么时候用：大促要出货给公众号头图 / 朋友圈方图 / 灯箱 / 易拉宝多个幅面；

【四、本轮真被抓出来并修掉的 6 个问题（这才是关卡的用处）】
  1. 抠图边缘白描边
     首轮渲染后，杯体轮廓在米色纸面上一圈偏白的灰边，一眼假。
     查因：u2net 抠图源是白底拍摄，掩膜是二值硬边，最外一圈像素还带着白底颜色。
     修法：alpha 通道腐蚀 2px + 0.7px 高斯恢复抗锯齿，只动掩膜不动像素。
     复核：过渡带像素 0 → 26465（c1 6339 / c4 6703 / c5 13423；有了正常抗锯齿带），
      且过渡带均值亮度低于米色底（L*=91.6），即轮廓不再比底色更白。

  2. 商品图之间的色号不一致
     6 张商品素材是各自独立生成的，量出来杯体 ΔE76 最大 48.49（判定线 4.0），
     等于同一套图里出现了不同颜色的杯子。
     修法：以首图为参考重出配套场景 / 特写 / 四色 / 手握四张（图生图 + 高保真度），
     再对四色排列图做 chroma 微校（只动 a*/b*，不动明度）。
     复核：按 Δ(a*, b*) 现量最终素材，macro 2.43 / scene 3.60 / lineup 0.52 / hand 2.06，
     全部 ≤ 4.0。ΔE76 里剩下的差异（如场景图 22.83）全部来自光线明度，不是色号。

  3. 划线价 ￥238（修了两次才算干净）
     初版海报右下写了 ￥238（删除线）+ ￥168 现价。
     依据：虚构原价属价格欺诈（《价格法》《禁止价格欺诈行为的规定》要求划线价须有
     真实成交依据），合规关卡应当拦下。
     修法 A：删掉海报那一处，改为单一定价 ￥168（标签 RETAIL）。
     修法 B（补漏）：售后保障章底部还有同一处划线价，第一次的补丁只改到海报那一处，
     漏了详情页这一处，已一并删除。
     关卡缺口如实记：当时的合规扫描只扫「从 HTML 抽出的文字」，
     价格在版面里、不在文字流里，所以漏检；本轮补了一道版面复扫才算闭掉。
     复核：全篇价格只剩 ￥168 一种，「价格合规」组归 0。

  4. 文案里的破折号与二元对比
     售后章原来写着「…会有细微差异——这是手作痕迹，不是瑕疵。」
     依据：去 AI 味规则第 2 条（不用「不是 X，而是 Y」二元对比）与第 6 条（不用破折号）。
     修法：改为「…会有细微差异，属手作痕迹。」
     复核：去 AI 味扫描归 0。

  5. 没有检测报告却宣称已送检
     信任背书章写「按 GB 4806.4 …标准送检，铅镉迁移量符合限值要求」，
     信息图右下角写「来源：GB 4806.4 检测报告 / 自有窑口实测」。
     问题：本轮的参数全部是占位值，没有对应批次的检测报告。
     宣称已送检、已符合限值属虚假宣传，也是这类详情页最容易被平台打回的一处。
     修法：改为「按 GB 4806.4 标准组织生产；铅镉迁移量以随批检测报告为准」，
     信息图来源行改为「参数为设计占位值 · 上线前替换为批次检测数据」。
     复核：版面复扫「检测 / 认证宣称」0 处。

  6. 逐张目检又抓出 8 处文案与版式问题（本轮第一次做完整目检）

       · 使用场景章标题断句：「清晨七点，桌上」→「清晨七点，桌上的一杯」
       · 核心卖点章第 3 行右值「380ml」与标题重复 → 改「≈3 杯手冲」
       · 细节特写章「落在木桌与纸上都不划痕」不成句 → 「…都不会划伤」
       · 首屏章右上「380ml」与底部规格行重复 → 改「No.01」，统一编号体系

【五、本轮诚实说明的三条限制（不藏）】
  1. 商品素材是 AI 生成的图，不是自有实拍。虽然已经做过色号统一与去边，
     但上架前仍建议换成自己的实拍图——特别是描金这类工艺细节，
     生成的质感与实际货品一定有差。
  2. 参数（380ml / 96mm / 3.4mm / 1280℃ / 262g / 0.8mm 金线）是本轮的占位值，
     上线前请整组替换为真实检测数据；没有检测报告就不要写「实测」「送检」——
     这条本轮就踩过一次，见上面第 5 个问题。
  3. 「详情页自检（pdp_check）」报了 3 项 mid 级「近空白行占比 84%–88%」，
     涉及痛点共鸣 / 信任背书 / 售后保障三章。这不是缺陷，是两个检查器的口径不同：
     card_audit 量的是死白带（最大连续空白带），判的是版式密度，这三章全部 PASS；
     pdp_check 量的是逐行墨量，杂志风的留白与账本式排版天然会命中它。
