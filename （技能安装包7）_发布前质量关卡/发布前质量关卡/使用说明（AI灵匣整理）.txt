# 发布前质量关卡

> 一次检查，两道把关：先查能不能发（合规），再查够不够好（质量），最后给一句能执行的结论。

## 这个技能能做什么

一个技能干两件事，顺序不能反。

**第一关 · 合规检测**——查「能不能发」。加载通用规则，再按平台叠加对应规则，逐项过：绝对化用语、绝对承诺、排他声明、医疗违规、虚假宣传、价格合规、违禁内容。

**第二关 · 产物质量审核**——查「够不够好」。按产物类型（文本 / 图片 / 视频）走不同维度，给三级结论：

| 结论 | 含义 |
|---|---|
| ✅ 通过 | 可直接发布 |
| ⚠️ 有瑕疵 | 建议微调后发布 |
| ❌ 不达标 | 需返工 |

**综合判定规则**（明确写死的）：合规高风险 → 整体 ❌；质量审核为 ❌ → 整体 ❌；合规低风险 + 质量 ✅ → 整体 ✅；**其他组合一律 ⚠️**。最后附 Top 3 优先修改建议。

**它是怎么给出结论的**：不是打分，是**给出处**。每条命中都带 `type` / `severity` / `text` / `reason` / `suggestion` 五个字段——原文哪一句、触了哪条规则、为什么、怎么改，一条条列出来。

## 什么时候用它

- 文案写完了，想在上架前查一遍有没有绝对化用语、违规承诺
- 详情页 / 主图 / 海报要发出去了，想知道有没有踩平台规则
- 图片、视频、文案混在一起的一批产物，想一次性过一遍完整性
- 客户或老板问「这个能不能发」，你不想凭感觉回答

**平台规则**只有小红书 / 抖音 / B站 三份加通用规则——**没有淘宝专项规则**。不传平台名就走通用规则，这在本包实测里同样能跑通（淘宝场景实测就是走通用规则通过的）。

**不适合的场景**：想问「这张图好不好看、为什么」——那是「审美原理与视觉评审」的活。这个关卡管合规与完整性，不管审美取舍。

## 需要准备什么

| 材料 | 说明 | 必需 |
|---|---|---|
| 待检查内容 | 文本直接贴进对话；图片 / 视频给路径 | 是 |
| 目标平台 | 小红书 / 抖音 / B站，或不说 | 否 |
| 证据材料 | 有出处的检测数据、官方榜单排名（想用「有据可查」放行时必给） | 否 |

**纯方法论技能**：目录下只有 `SKILL.md` 和 `references/`，**没有 `scripts/`、不提供任何命令行**。输入靠你把文字贴进对话、图片或视频给路径。

**给内容时有个关键技巧**：**只贴面向消费者的那部分文案**。自检表、规则表里「列举禁词本身」的那些行必须排除，否则技能自己列的禁词表会被自己命中，报出一堆假阳性。

## 操作步骤

### 第 1 步：给它内容与平台

直接说：把这段文案过一遍合规，发小红书。

### 第 2 步：它跑第一关（合规）

读内容 → 加载通用规则 → 按平台叠加规则 → 逐项检测 → 汇总合规结果（含 `risk_level` 与 `passed_checks`）。

### 第 3 步：它跑第二关（质量）

识别产物类型 → 按维度逐项检查 → 给三级结论 → 结论为 ❌ 时附返工指引。

### 第 4 步：拿综合判定与 Top 3 修改建议

输出是一段 JSON（结构见下），你只要看 `overall_verdict` 和 `top_fixes` 两个字段。

```json
{
  "overall_verdict": "✅ 可发布 | ⚠️ 需修改 | ❌ 不达标",
  "platform": "平台名或 generic",
  "compliance": {
    "risk_level": "low|medium|high",
    "issues": [{ "type": "", "severity": "", "text": "", "reason": "", "suggestion": "" }],
    "passed_checks": []
  },
  "quality": {
    "score": "✅|⚠️|❌",
    "dimensions": [{ "name": "", "score": "", "note": "" }]
  },
  "top_fixes": ["修改建议1", "修改建议2", "修改建议3"]
}
```

## 命令速查

本技能**没有命令行**，只有对话调用。

| 你怎么说 | 它做什么 |
|---|---|
| 「检查合规」/「有没有敏感词」 | 跑第一关，逐项列命中 |
| 「审核一下」/「质量够不够」 | 跑第二关，按维度给结论 |
| 「能不能发」 | 两关都跑，给综合判定 + Top 3 |
| 「按小红书规则查」 | 叠加小红书专项规则 |
| 「按抖音规则查」 | 叠加抖音专项规则 |

按平台追加的规则只有三个平台名可写：**小红书 / 抖音 / B站**。

质量审核的维度按产物类型自动切换：文本走完整性 / 可读性等维度；图片走文件存在、尺寸格式、内容匹配；视频再加时长与拼接。

## 你会拿到什么

- 一段 JSON 判定：`overall_verdict`、`compliance`、`quality`、`top_fixes`
- 合规命中的逐条明细（每条带原文、原因、建议）
- 质量审核各维度的分数与说明
- 结论为 ❌ 时附返工指引

## 完整对话案例

### 实测：8 章详情页文案 + 5 张主图文案的完整过卡记录

检查对象：`05_文案/01_详情页文案.md`（8 章）+ `02_主图文案.txt`（5 张主图）；检查日期 2026-09-19；**Profile：无（走通用规则）**——也就是淘宝场景实测走的是通用规则。

**第一关 · 合规：七组全部 0 命中**

| 规则组 | 命中 | 明细 |
|---|---|---|
| 绝对化用语 | 0 | — |
| 绝对承诺 | 0 | — |
| 排他声明 | 0 | — |
| 医疗违规 | 0 | — |
| 虚假宣传 | 0 | — |
| 价格合规 | 0 | — |
| 违禁内容 | 0 | — |

**但关卡真的拦下了一条（而且是这条把关卡的价值体现出来了）：**

> **现象**：初版海报右下角写了 `￥238`（带删除线）+ `￥168` 现价。
> **依据**：《价格法》《禁止价格欺诈行为的规定》要求划线价必须有真实成交依据，凭空标一个更高的「原价」属**虚构原价 / 价格欺诈**。命中「价格合规」规则组。
> **处理**：删除划线价，改为 `RETAIL / ￥168` 单一定价，重渲海报后复查该规则组归零。

**第二关 · 质量：五维度全 ✅**

| 维度 | 结论 | 依据 |
|---|---|---|
| 完整性 | ✅ | 5 主图 + 8 章详情页 + 长图 750×8664 + 9 段切图 + 海报 + 信息图 + 2 GIF |
| 可读性 | ✅ | 逐张读图复核，正文最小字号 22px（750 宽画布），未发现压字 / 截字 |
| 平台适配 | ✅ | 主图 1200×1200（平台建议 ≤1200）、详情页 750 宽、单张体积 ≤1.7MB |
| 设计一致性 | ✅ | 杯体 ΔL* 随光线变化（物理正确），Δ(a*,b*) 全部 ≤4.0 |
| 版式密度 | ✅ | card_audit 10/10 PASS，死空白 span ≤0.89、max_gap ≤0.132 |

**综合判定：⚠️ 需修改 → 修复后 ✅ 可发布。** 注意这个 ⚠️ 是**规则本身要求的**——只要不是「合规低风险 + 质量 ✅」的完美组合，就一律判 ⚠️，不是在挑刺。

### 关卡漏检了一次，如实记（这是本包最有价值的一条实测）

关卡的第一版只扫了**从 HTML 抽出的文字**。而价格在**版面里**，不在文字流里——所以底稿里的 `￥238` 划线价被漏掉了。

补法：本轮另加了一道**版面复扫**（直接查渲染前的 HTML 里的删除线样式与价格串）。复扫结果：

```
"r1_struck_price": [],          ← 删除线 + 价格：0 处
"r2_cert_claim": [],            ← 检测 / 认证宣称：0 处
"pass": true
```

顺带还扫出并修掉了另一处：详情页信任背书章原写「按 GB 4806.4 标准**送检**，铅镉迁移量**符合限值要求**」——本包参数全是占位值、没有对应批次检测报告，这句属虚假宣传。已改为「按 GB 4806.4 食品接触用陶瓷制品标准组织生产；铅镉迁移量以随批检测报告为准」。

**结论：文本合规关卡要过，版面也要另过一道。** 这两道加起来才是完整的「能不能发」。

## 常见问题 FAQ

**Q1：它会不会把我自己列的禁词表也命中一遍？**
A：会。所以**扫描口径要只扫面向消费者的文案行**，自检表、规则表里「列举禁词本身」的那些行必须排除。给内容时最好只贴对外发布的那部分文字。

**Q2：我写了「淘宝」，它会按淘宝规则查吗？**
A：**不会**。平台规则只有小红书 / 抖音 / B站三份加通用规则；传规则里没有的平台名**不会报错，会静默退回默认规则集**。别以为它在按你那个平台查——平台名就照那三种写，淘宝场景就走通用规则（本包实测就是这么跑通的）。

**Q3：图片上的文字会被扫到吗？**
A：**不会**。图片与视频类产物的审核维度只有文件存在、尺寸格式、内容匹配（视频再加时长与拼接）；**图上烧进画面的文字不在扫描维度里**。主图、详情页图上的标语要把原文一起**以文本形式**给它才不会被漏掉。

**Q4：想让「有据可查」这条放行原则生效，要准备什么？**
A：合规侧的判定依赖你能提供的证据。引用官方榜单的排名、有出处的检测数据要一并给出，否则这条原则用不上。

**Q5：它会不会嫌我的设计不够美？**
A：不会。质量审核**宽进严出**：风格偏好、不够完美都不会被判 ❌。它只管任务是否完成、质量是否达标——不要指望它替你做审美取舍。

**Q6：洗稿相似度、素材授权链路会查吗？**
A：不会。这类深度检测不在本关卡内（SKILL.md 指向 `skill-risk-scanner`，**该技能没有随本包提供**），有需求要单独处理。

**Q7：返工几次？**
A：返工上限 **1 次**。第二次仍不达标就照常交付，务必看它附的问题说明——**别默认「过了关卡就一切没问题」**。
