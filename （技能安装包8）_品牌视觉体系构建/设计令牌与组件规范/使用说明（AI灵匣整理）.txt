# 设计令牌与组件规范

> 把「主色 #FF6B35」这类口头约束，变成代码里真能引用的变量，再用校验脚本揪出硬编码。

## 这个技能能做什么

**核心是三层令牌架构。**这是它跟「随手定义几个 CSS 变量」的本质区别：

```
原始层 Primitive（裸值）
      ↓
语义层 Semantic（用途别名）
      ↓
组件层 Component（逐个组件专用）
```

SKILL.md 给的原文示例：

```css
/* 原始层 */
--color-blue-600: #2563EB;

/* 语义层 */
--color-primary: var(--color-blue-600);

/* 组件层 */
--button-bg: var(--color-primary);
```

**为什么必须分三层**（SKILL.md 的 Best Practices 原话）：
1. 组件里**永远不许出现裸 hex**，一律引用令牌
2. **语义层让换主题成为可能**（浅色/深色切换只改语义层）
3. **组件层让单个组件可单独定制**，不影响其它
4. 透明度控制用 **HSL** 格式
5. **每个令牌都要记录用途**
6. 演示稿必须 import `design-tokens.css` 并**只用 `var()`**

**组件规格的写法**（SKILL.md 的 `Component Spec Pattern` 原表）：

| 属性 | 默认 | Hover | Active | Disabled |
|---|---|---|---|---|
| Background | primary | primary-dark | primary-darker | muted |
| Text | white | white | white | muted-fg |
| Border | none | none | none | muted-border |
| Shadow | sm | md | none | none |

**除了令牌，它还带一套演示稿系统**（Slides）：用令牌 + Chart.js + 一套**上下文决策系统**生成品牌合规的演示稿。决策系统由 8 份 CSV 充当知识库：

| CSV | 内容 |
|---|---|
| `slide-strategies.csv` | 15 种稿子结构 + 情绪弧 + 火花线节拍 |
| `slide-layouts.csv` | 25 种版式 + 组件变体 + 动效 |
| `slide-layout-logic.csv` | 目标 → 版式 + 是否破格（break_pattern） |
| `slide-typography.csv` | 内容类型 → 字阶 |
| `slide-color-logic.csv` | 情绪 → 用色处理 |
| `slide-backgrounds.csv` | 幻灯片类型 → 图片类别（Pexels / Unsplash） |
| `slide-copy.csv` | 25 条文案公式（PAS / AIDA / FAB） |
| `slide-charts.csv` | 25 种图表及其 Chart.js 配置 |

**破格逻辑（Duarte Sparkline）**：高级稿子在两种情绪之间交替来维持注意力——`"What Is"`（挫败）↔ `"What Could Be"`（希望）——系统在 **1/3 与 2/3 位置**自动算破格点。

## 什么时候用它

- 要把「主色 #FF6B35」这类口头约束，变成代码里真能引用的变量
- 需要统一的间距与字阶，避免每张图各写一套数值
- 要把品牌规范落成组件规格，交给开发或外包执行
- 要一套浅色/深色能一键切换的主题体系
- 要做一份**品牌调性统一**的演示稿（不是随便套个模板）

**同包内怎么选**：
- 要 Logo、CIP 样机、图标、社媒图 → 用「全案设计流程」，这个只做令牌与规范这一层
- 还不知道定什么调性，要先拿方向 → 先用「设计咨询与风格定调」

## 需要准备什么

| 材料 | 说明 | 必需 |
|---|---|---|
| 品牌色 / 字体 | 令牌的原始值来源 | 是（或先跑设计咨询） |
| 目标技术栈 | Tailwind / shadcn-ui / 纯 CSS | 否（默认 Tailwind 路线） |
| 组件清单 | 要定义哪些组件（按钮、卡片、表单…） | 否 |

**环境**：`generate-tokens.cjs` 与 `validate-tokens.cjs` 是 **Node 脚本（`.cjs`）**，需要本机有 Node；`search-slides.py` 等 5 个是 Python 脚本。**本机实测环境同时具备 Node 与 Python**，两条线都能跑。

**模板现成**：`templates/design-tokens-starter.json`（7184 B）就是一个填好三层结构的起始 JSON，照它改比从零写快得多。

## 操作步骤

### 第 1 步：从起始模板建令牌配置

复制 `templates/design-tokens-starter.json`，按品牌色与字体改原始层。

### 第 2 步：生成 CSS 变量

```bash
node scripts/generate-tokens.cjs --config tokens.json -o tokens.css
```

### 第 3 步：校验，把硬编码揪出来

```bash
node scripts/validate-tokens.cjs --dir src/
```

它会扫你的代码，找出**本该用 `var(--xxx)` 却写了裸 hex 或裸字体名**的地方。这一步是所有「令牌体系」能不能真落地、而不是墙上一张规范图的关键。

### 第 4 步（可选）：要出演示稿时，先查决策系统

```bash
# 基础检索（自动判断域）
python scripts/search-slides.py "investor pitch"

# 指定域检索：文案 / 图表
python scripts/search-slides.py "problem agitation" -d copy
python scripts/search-slides.py "revenue growth" -d chart

# 上下文检索（高级）：带位置与上一页情绪
python scripts/search-slides.py "problem slide" --context --position 2 --total 9
python scripts/search-slides.py "cta" --context --position 9 --prev-emotion frustration
```

### 第 5 步：生成演示 HTML 后校验令牌合规

```bash
python scripts/slide-token-validator.py
```

**合规的写法 vs 不合规的写法**（SKILL.md 原文对照）：

```css
/* 对 —— 用令牌 */
background: var(--slide-bg);
color: var(--color-primary);
font-family: var(--typography-font-heading);

/* 错 —— 硬编码 */
background: #0D0D0D;
color: #FF6B6B;
font-family: 'Space Grotesk';
```

**两件必须如实说的事：**

**① 它自己标了风险。**推荐风格 `Liquid Glass` 后面跟着 `Performance: ⚠ Moderate-Poor`（性能较差）与 `Accessibility: ⚠ Text contrast`（文字对比有风险）。**这个自带的警示是真实存在的，本说明书照原样抄下来，不删。**任何号称「技能推荐 = 最佳方案」的说法都是不诚实的。

**② 最终交付没有采用这个方向。**本包落地的是米色纸面 + 描金的中式静物体系。原因是陶瓷礼品的受众与「流动玻璃 + 动态模糊」不搭——**技能给的是有出处的候选，取舍由人做**。

**但它的 `Pre-Delivery Checklist` 是真用上了的**：其中「Light mode: text contrast 4.5:1 minimum」这一条，对应到本包实测里落成的**「文字对比最小值」口径**（见交付物打分表，本项目评审记录中最差一例 **7.07:1**，高于 4.5:1 的下限）。**一条 checklist 项被真的量成了数，这就是它和「墙上一张规范图」的区别。**

## 常见问题 FAQ

**Q1：`.cjs` 脚本要装什么？**
A：要本机有 **Node.js**。本机实测环境具备（Node 22.22.2），直接 `node scripts/generate-tokens.cjs ...` 即可，不需要额外 npm 包。

**Q2：`validate-tokens.cjs` 是干什么的？**
A：扫你的代码目录，找出本该用 `var(--xxx)` 却写了裸 hex / 裸字体名的地方。**它是这套体系能不能落地的关键一步**——没有它，令牌就是一份谁都不遵守的文档。

**Q3：`--dir src/` 里的 `src/` 指哪？**
A：相对于**当前工作目录**（也就是你的项目根）。脚本按项目根读写 `docs/`、`assets/`、`src/` 这类路径。

**Q4：演示稿必须用 Chart.js 吗？**
A：SKILL.md 的硬性要求是「**用 Chart.js 画图，不是纯 CSS 柱子**」。纯 CSS 柱状图在这套体系里算不合规。

**Q5：演示稿必须 import `design-tokens.css` 吗？**
A：必须。SKILL.md 把它列为「**ALL slides MUST**」的第 1 条，并且要求**只用 `var()`**、不许写裸值。

**Q6：`search-slides.py` 要不要联网？**
A：不要。它检索的是技能自带的 8 份 CSV。**只有 `fetch-background.py`（从 Pexels / Unsplash 取图）需要联网。**

**Q7：`--prev-emotion` 有什么用？**
A：用来算破格点。高级稿子要在「挫败 ↔ 希望」之间交替，系统按 1/3 与 2/3 位置自动安排破格。不传也能跑，只是少一层上下文判断。

**Q8：跟同包的「全案设计流程」什么关系？**
A：它是「全案设计流程」路由表里的同级子技能之一（`design-system`）。**本包两个都装了**，只用令牌与规范这一层时，直接调本技能更聚焦。

## 注意

- 脚本分两种：`generate-tokens.cjs` / `validate-tokens.cjs` 是 **Node（`.cjs`）**，其余三个是 **Python**。两条线都需要本机有对应运行时。
- **脚本路径相对于 SKILL.md 所在目录，不是相对于项目目录**：`scripts/<file>` 是技能自己的，`../<skill>/scripts/<file>` 是同级子技能的。工作目录保持在项目根，脚本默认读写 `docs/brand-guidelines.md`、`assets/design-tokens.json`、`src/` 这类项目文件。
- **组件里永远不许出现裸 hex**，一律引用令牌；语义层让浅色/深色切换只改一处；组件层让单个组件可单独定制。
- **透明度控制用 HSL 格式**；每个令牌都要记录用途。
- **演示稿的 6 条硬性要求**：① import `assets/design-tokens.css` ② 只用 `var(--xxx)` ③ 用 Chart.js 画图（不许 CSS 柱子）④ 带导航（键盘方向键、点击、进度条）⑤ 内容居中 ⑥ 以说服/转化为目标。
- **破格点在 1/3 与 2/3 位置**（Duarte Sparkline 的 `What Is` ↔ `What Could Be` 交替），这是系统算出来的，不是随便插一页。
- `fetch-background.py` 依赖 **Pexels / Unsplash**，需要联网与相应凭据；不使用外网图时这条线可跳过。
- **Skill Dependencies 标注为 `brand` 与 `ui-styling`**，**这两个技能本包没有提供**。品牌识别（色调、语气）与 UI 代码落地（Tailwind / shadcn-ui 配置）这两段请另找技能；令牌层与规范层本技能自身完备。
- 本技能作者标注为 `claudekit`（frontmatter `metadata.author`），版本 `1.0.0`，`license: MIT`。
- 本技能没有 `EASEL-META.md`：从公共开源仓库整包收录，来源与许可记录在自带 frontmatter 里。
