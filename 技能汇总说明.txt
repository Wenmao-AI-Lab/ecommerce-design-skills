     其余 17 个平台（含国内六个）的官方页被登录墙或 JS 挡住，用的是行业常见值，
     平台矩阵里逐条标了 source_tier 与 confidence，上传前必须到自己后台再核一遍。

     同口径产品区细节只高 +3.0%~+7.6%（见后文「第三轮实测」）——尺寸达标不等于观感达标。
  3. 国内平台普遍要求首图白底无文字，而带字版每张都带卖点文字 —— 首图位要用净版，

   实测：母版档 1.030 ~ 1.076x，中位 1.059x，全档位最小 1.022x → 判定「可接入」。
   不设 ECOM_CUT_DIR 就仍用原抠图，整条通道可关；裁边缓存按来源目录分名，不会复用旧的低清裁块。

本轮新增的限制（在原四条之上）：
  5. 超分只在放大区间兑现：母版档产品区 +3.0%~+7.6%，但缩到 160px 的缩略图口径只剩
     +1.4%（评分里那一项 4.22→4.28）；原图本身糊的素材救不回来。

  7. 六张送超分的素材里有一张（orange）从未进入任何成品，它是换配色的备用图；

     第四轮实测：把"设计感不强"变成六道拦得住的关卡（2026-09-19）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

起因是用户一句话："全套图片是出来了，但设计感不强、不美观。"
前几轮的分数（94.8）量的是对齐、亮度、对比、一致性，这些全绿灯的图仍然可以不好看。
本轮不猜"哪里不好看"，先按 `审美原理与视觉评审`（aesthetic-foundations）的 7 步评审协议
（三秒第一印象 / 眯眼 / 灰度 / 留白 / 裁剪 / 大师参照 / 改动清单）把整套图过一遍，
再把每一步的结论换成一个能复跑的测量口径。

   修不了的两条如实留着：素材只有 6 个角度、场景章没有真实环境
   （ImageGen 403；Wikimedia 超时，Unsplash 401，Pexels 403，Amazon 详情页反爬）。
   逐条证据：`_audit/设计感缺口与外部技能判定_第四轮实测.md` §1。

⑥ 收尾抓到的第五个"规则在、执行者不在"：描述产物的文档会自己过期

   （只查数值会被"两轮恰好同值"绕过）；证据里的每个总分必须原样出现在文档正文里

三、这一轮真正抓到并修掉的六个问题（这才是关卡存在的意义）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. 抠图边缘白描边
   首轮渲染出来，杯体轮廓在米色纸面上有一圈偏白的灰边，一眼就假。
   查因：u2net 抠图源自白底拍摄，alpha 掩膜是二值硬边（实测过渡带像素 0），
   掩膜最外一圈像素还带着白底的颜色，贴到米色底上就发白。
   修法：alpha 通道 MinFilter(5) 腐蚀 2px + GaussianBlur(0.7) 恢复抗锯齿；
   只改掩膜，不动任何像素颜色。
   复核：轮廓过渡带像素 0 → 26465（c1 6339 px / c4 6703 px / c5 13423 px），
   且过渡带均值亮度 L* 为 71.2 / 55.4 / 52.1，低于米色底（L*=91.6），即不再比底色更白。

2. 六张商品图之间色号不一致
   六张素材是各自独立生成的，量出来杯体 ΔE76 最大 48.49（判定线 4.0）——
   等于同一套图里出现了不同颜色的杯子，这是「一眼假」的第二个来源。
   修法：① 以首图真品为参考做图生图（高保真度）重出场景 / 微距 / 四色 / 手握四张；
        ② 对四色排列图做 chroma 微校（只移动 a*/b*，不动明度）；
        ③ 替换素材源，旧素材留 _v1 备份。
   复核：按 Δ(a*,b*) 现量最终素材，macro 2.43 / scene 3.60 / lineup 0.52 / hand 2.06，全部 ≤ 4.0。
   明度 L* 的差异来自各张光线条件不同，属物理正确，没有拉平——
   把不同光照下的白瓷强行拉成同一亮度，反而会像贴纸。

3. 划线价 ￥238（合规关卡拦下，本轮补漏一次）
   初版海报右下角写了 ￥238（删除线）+ ￥168 现价。
   依据：划线价必须有真实成交依据（《价格法》《禁止价格欺诈行为的规定》），
   凭空标一个更高的「原价」属价格欺诈。
   修法 A：删掉海报那一处，改单一定价 ￥168，重渲海报。
   修法 B（本轮补漏）：售后保障章底部还有同一处划线价，上一轮的补丁只改到海报，
   漏了这一处，本轮一并删除。复核：全篇价格只剩 ￥168 一种。
   关卡缺口如实记：上一轮的合规扫描只扫「从 HTML 抽出的文字」，
   价格在版面里、不在文字流里，所以漏检；本轮补了一道版面复扫才算闭掉。

4. 文案里的破折号与二元对比（去 AI 味关卡拦下）

5. 没有检测报告却宣称已送检（本轮新拦下）

        → 空行 →【详细概述】→ 空三行 → 正文（# 标题 / > 一句话定位 /
        ## 这个技能能做什么 / 什么时候用它 / 需要准备什么 / 操作步骤 /

二、每份说明书里写了什么（内容来源逐类可查）
─────────────────────────────────────────────────────────────
  · 【技能标识】【功能描述】—— 取自各 zip 内 SKILL.md 的 YAML frontmatter
    （name / description），是技能本体里的原值，不是重新编的。
  · 【所属分类】—— 取自安装目录名（（技能安装包N）_阶段名）。
  · 命令速查表的参数 —— 用正则从技能真实脚本的 argparse 定义里抽出来
    （add_argument / add_parser），不是照文档抄的，所以不会出现
    「文档写的参数和代码里的不一样」。
  · 完整对话案例、注意、修复记录 —— 取自本包五轮实测的原始记录：
