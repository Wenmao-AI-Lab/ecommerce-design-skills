# 多图合成与导出

> 7 种版式一次成型：自动统一色温、对齐拼缝、加编号角标，再按 7 个平台尺寸批量导出。

## 这个技能能做什么

拼版这件事手工最耗时间，而且极容易对不齐。这个技能把它做成参数化操作——你给图和版式，它给你一张**尺寸完全自洽**的成品。

**7 种内置版式**（下表是代码 `scripts/composer.py` 里 `LAYOUTS` 的真实定义，含各自默认间隙与边距）：

| 版式 | 说明 | 默认 gap | 默认 pad |
|---|---|---|---|
| `grid3` | 九宫格 3×3（不足 9 张自动补位为 N×M） | 12 | 12 |
| `grid2` | 四宫格 2×2 | 14 | 14 |
| `strip` | 纵向长图（单列依次排列） | 10 | 10 |
| `strip2` | 双列长图 | 12 | 12 |
| `compare` | 左右对比（前一半放左、后一半放右） | 20 | 20 |
| `masonry` | 瀑布流（双列、高度自适应） | 10 | 10 |
| `hero` | 一大四小（首图放大，其余四张在下方） | 12 | 12 |

> ⚠️ 技能自带的 SKILL.md 只列了 6 个版式，**漏了 `grid2`**。本说明按代码补全为 7 个——上面这张表比 SKILL.md 准。

**它在拼的时候自动做 4 件事：**
1. **统一白平衡**：把各图色温往同一基准拉，避免相邻两格一个偏黄一个偏青（`--unify-wb`）
2. **对齐拼缝**：所有间隙等宽，四边留白对称
3. **加编号角标**：可选，用 `--labels` 传 `{"1":"正视图","2":"侧面细节"}`
4. **统一单元尺寸**：把长宽比不同的输入自动裁成同一个单元框

**拼完还有一道结构检查器**（`composer_check.py`）：查单元尺寸是否完全一致、拼缝是否等宽、相邻单元有没有色温突变——注意它靠 `--input` 同目录下的 `合成报告.json` 工作，所以**必须由 `composer.py` 跑过才有得查**。

## 什么时候用它

- 要把多张细节图拼成一张长图放进详情页
- 要做多色 / 多款对比图（`compare`）
- 要做九宫格（小红书 / 朋友圈风格，`grid3`）
- 要有主次的「一大四小」版面（`hero`）
- 拼完要按不同平台尺寸分别导出，而不是同一张图硬缩

**不适合的场景**：只是把 8 个详情页章节纵向接成一张整页长图（那是「详情页拼合与章节编排」的活，它管章节顺序、索引与切图）；只是改尺寸加水印（那是「通用图像处理加工」）。

## 需要准备什么

| 材料 | 说明 | 必需 |
|---|---|---|
| 输入图 | 2~12 张，建议长宽比一致 | 是 |
| 版式 | 上表 7 种之一 | 是 |
| 每图标签 | 如「正视图」「侧面细节」，走 `--labels` | 否 |
| 输出目录 | `--out` 是**目录**不是文件名 | 是 |

**环境**：脚本随本技能自带（`scripts/` 下 4 个文件），需要本机有 Python 3.8+ 与 Pillow。

**关于输入图的长宽比**：不一致时默认 `--fit cover` 会裁掉边；要完整显示用 `--fit contain`，代价是补白边——但白边铺进固定图框会被卡片质检判成死空白，稳妥做法是**先紧裁到内容外接框**再拼。

## 操作步骤

### 第 1 步：先看有哪些版式

```bash
python scripts/composer.py --list
```

### 第 2 步：合成

```bash
# 四宫格，带标签
python scripts/composer.py --layout grid2 --input 细节图/ --labels labels.json --out _r/四宫格

# 九宫格，直接按总宽出图（推荐：避免后期放大发糊）
python scripts/composer.py --layout grid3 --input 细节图/ --unify-wb --width 790 --out _r/九宫格

# 一大四小
python scripts/composer.py --layout hero --input 1.jpg,2.jpg,3.jpg,4.jpg,5.jpg --unify-wb --out _r/主视觉

# 纵向长图，强制统一单元尺寸
python scripts/composer.py --layout strip --input 细节图/ --unit 400x400 --width 420 --out _r/长图

# 左右对比
python scripts/composer.py --layout compare --input 本款.jpg,竞品.jpg --out _r/对比
```

### 第 3 步：检查拼缝一致性

```bash
python scripts/composer_check.py --input _r/四宫格/合成图.png --layout grid2 --out _r/检查
```

### 第 4 步：按平台导出

```bash
python scripts/composer_export.py --input _r/九宫格/合成图.png --platforms 淘宝,小红书,抖音小店 --out _r/导出
```

`--mode width` 只等比缩到平台宽（默认）；`cover` / `contain` 按平台主图尺寸处理。

## 命令速查

**`composer.py`** —— 合成

| 参数 | 说明 |
|---|---|
| `--list` | 列出所有版式 |
| `--layout` | 版式名（7 选 1） |
| `--input` | 输入图：目录、逗号分隔的文件列表，或 `--dir` |
| `--unit WxH` | 强制统一单元尺寸，如 `400x400` |
| `--width` | 指定总宽，自动推导单元尺寸（**推荐直接用它出目标宽度**） |
| `--labels` | JSON：`{"1":"正视图","2":"侧面细节"}` |
| `--unify-wb` | 统一白平衡 |
| `--fit` | `cover`（默认，裁边）/ `contain`（补白边） |
| `--out` | **输出目录**（不是文件名） |

**`composer_check.py`** —— 拼缝与结构检查

| 参数 | 说明 |
|---|---|
| `--input` | 合成图路径（同目录需有 `合成报告.json`） |
| `--layout` | 版式名 |
| `--out` | 检查报告输出目录 |

**`composer_export.py`** —— 多平台导出

| 参数 | 说明 |
|---|---|
| `--input` | 合成图 |
| `--platforms` | 逗号分隔，认这 7 个：`淘宝` `京东` `拼多多` `抖音小店` `小红书` `快手` `1688` |
| `--mode` | `width`（默认）/ `cover` / `contain` |
| `--suffix` | 输出文件名后缀 |
| `--out` | 输出目录 |

各平台主图尺寸（代码 `_common.py` 的 `PLATFORMS` 原值）：淘宝/天猫、京东、拼多多、抖音小店、快手、1688 均为 `800×800`，小红书为 `1242×1660`；详情页宽淘宝/京东/1688 为 `790`，拼多多/抖音/小红书/快手为 `750`。

## 你会拿到什么

- `合成图.png` —— 拼好的成品（同时出一份 `.jpg`）
- `合成报告.json` —— 版式、单元尺寸、间隙、边距、画布尺寸、每格坐标、`skipped` 列表
- `导出/<平台>/` —— 分平台尺寸版本 + `导出报告.json`
- `拼缝检查.md` —— 单元尺寸 / 拼缝等宽 / 色温突变 三项检查结果

## 完整对话案例

### 实测：一个商品的四组版式全跑通（本包全流程实测记录）

素材是同一只马克杯的 6 张图（4 张实拍 + 2 张场景）。四组版式的实际参数与产物：

| 版式 | 输入 | 单元 | 间隙 | 边距 | 画布 | 跳过 |
|---|---|---|---|---|---|---|
| `grid2` 四宫格 | 4 张 | 400×364 | 14 | 14 | **842×770** | 0 |
| `hero` 一大四小 | 5 张 | 400×364 | 12 | 12 | **836×1128** | 0 |
| `strip` 纵向长图 | 4 张 | 400×364 | 10 | 10 | **420×1506** | 0 |
| `compare` 左右对比 | 2 张 | 400×364 | 20 | 20 | **860×404** | 0 |

四组全部开 `--unify-wb`、`--fit cover`，`skipped` 全为 0（没有被静默丢掉的图）。控制台原话：

```
合成完成：版式 grid2
  输入 4 张（跳过 0 张）
  单元 400x364  间隙 14  边距 14
  画布 842x770
```

**算得回来**：842 = 14×2（边距） + 400×2（两列） + 14（间隙）＝ 28 + 800 + 14 ✓
770 = 14×2 + 364×2 + 14 ＝ 28 + 728 + 14 ✓

`strip` 的 1506 = 10×2 + 364×4 + 10×3 ＝ 20 + 1456 + 30 ✓ —— **画布尺寸完全自洽，拼接没有多一像素也没有少一像素**。

**一个实用结论**：四宫格 400×364 的单元偏小（842 px 总宽不足 750 详情页宽的两倍），要进详情页就把 `--width 1500` 交给它自己推导单元尺寸，别拼完再放大。

## 常见问题 FAQ

**Q1：`--out` 后面写文件名，它说「产物已存在」？**
A：`--out` 是**目录**，脚本固定往里写 `合成图.png`。同一目录已存在该文件时会**直接报错退出，不静默覆盖**——换 `--out` 或先清掉旧的。

**Q2：`composer_check.py` 报「缺少合成报告」？**
A：它靠 `--input` 同目录下的 `合成报告.json` 做结构校验。没有这份报告只能报这一句，得先用 `composer.py` 重新合成一次，才能查出真问题。

**Q3：`--platforms` 写了个不认识的平台名，为什么不报错？**
A：它会**静默退回只出淘宝一档**。交片前请核对 `导出报告.json` 里的 `n` 与导出目录数量，别以为它按你写的那几个都出了。

**Q4：拼出来相邻两格颜色明显不一样？**
A：拍图色温不统一。加 `--unify-wb` 重合成。

**Q5：拼缝忽宽忽窄？**
A：输入图尺寸不齐。用 `--unit 400x400` 强制统一单元尺寸。

**Q6：导出后糊了？**
A：放大导致插值失真。**要多宽就在 `--width` 里给多宽**，不要后期放大。

**Q7：给了 7 张图做 `hero`，为什么只进了 5 张？**
A：`hero` 版式只取首图放大 + 其后 4 张，多给的图不进版面。

**Q8：`masonry` / `hero` 会不会被检查器判「单元尺寸不一致」？**
A：不会。这两版的单元高度天然不等，已豁免该检查。

## 注意

- **`--out` 是目录不是文件名**，脚本固定写 `合成图.png`；已存在就报「产物已存在」退出，不静默覆盖。
- **`composer_check.py` 依赖同目录的 `合成报告.json`**，没有它只会报「缺少合成报告」，必须先用 `composer.py` 重新合成才能查出真问题。
- 长宽比不一致时默认 `--fit cover` 会裁边；`--fit contain` 补白边，**但白边铺进固定图框会被卡片质检判成死空白**，先紧裁到内容外接框更稳。
- `hero` 只取首图 + 其后 4 张；`masonry` 与 `hero` 单元高度天然不等，这两版已豁免「单元尺寸一致」检查。
- `--platforms` 写了不认识的词**不报错，静默退回只出淘宝一档**——交片前核对 `导出报告.json` 的 `n` 与导出目录数量。
- `--unit` 必须是 `宽x高` 格式（如 `400x400`），格式错直接退出；`--width` 太小导致单元宽 < 40px 也会拒绝出图。
- **别指望拼完再放大**：要多宽就在 `--width` 里给多宽，后期放大会插值发糊。
- 读不了的图只打一行「⚠ 跳过」，会**静默少一格**——务必看 `合成报告.json` 的 `skipped` 字段。
- 命令里的 `scripts/xxx.py` 是技能文档的原样写法，需在技能目录下执行；实际路径在你安装的技能目录下的 `multi-shot-composer/scripts/`。产物建议按本包统一布局放 `outputs/<具体主题>/`——泛名 `output` / `test` / `临时` 会被公共运行库的 `output_paths.py` 拒绝写盘。
- 本技能没有 `EASEL-META.md`（技能自带 frontmatter 的 `license: MIT` 已够用）。

## 修复记录

- **本包未改动技能本体。** zip 内 5 个文件与本机实测所用安装版本**逐文件 MD5 一致**（`scripts/composer.py`、`composer_check.py`、`composer_export.py`、`_common.py`、`SKILL.md`），比对方式与结果见下表。
- **本包全流程实测中，本技能被实际调用 4 次**，四组版式（`grid2` / `hero` / `strip` / `compare`）全部 rc=0 跑通，`skipped` 全为 0，画布尺寸逐项算得回来（详见「完整对话案例」）。原始日志在交付物 `07_过程档案/03_合成_2*.txt`，报告在 `_tmp/compose/*/合成报告.json`。
- **发现一处文档缺口（如实记，未擅自改技能）**：技能自带 SKILL.md 的「内置版式」只列了 6 个（`grid3` / `strip` / `strip2` / `compare` / `masonry` / `hero`），但 `scripts/composer.py` 的 `LAYOUTS` 实际有 **7 个**——漏了 `grid2`（四宫格 2×2），而本包实测恰恰用了它。本说明书的版式表按代码补全为 7 个。这是文档与实现不一致，**不是技能坏了**，所以没有改 zip。
- **一处措辞澄清**：SKILL.md 写「九宫格 3×3、不足 9 张自动补位为 N×M」，实际补位规则是按张数推导 N×M 网格；用 4 张图跑 `grid3` 会得到 2×2，不会留 5 个空格。要精确控制版面时直接用 `grid2`。
