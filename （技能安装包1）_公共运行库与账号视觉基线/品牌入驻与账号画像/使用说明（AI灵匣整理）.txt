# 品牌入驻与账号画像

> 先采集公开信息，再问用户补缺口——产出的六件套档案是后面每一个出图技能的「锁色板 + 语气表 + 红线清单」。

## 这个技能能做什么

建一份**机器可读**的账号画像，六个文件各有分工：

| 文件 | 里面是什么 | 谁在消费它 |
|---|---|---|
| `identity.md` | 品牌名、定位、使命、差异化、核心产品 | 海报底部署名、文案开头 |
| `style.md` | 视觉风格、语气调性、内容节奏、Do / Don't | 所有出图技能的配色与字体来源 |
| `audience.md` | 目标人群、用户语言、痛点与需求 | 文案技能选词、卖点角度 |
| `platforms.md` | 各平台账号、发布频率、标签策略 | 图像处理技能的默认输出比例 |
| `preferences.md` | 内容支柱、主推产品、禁区话题、合规底线 | 文案与质检技能的红线 |
| `memory.md` | 初始空模板，由后续投放回写 | 归因层 |

五个阶段推进：`Phase 0` 环境准备 → `Phase 1` 公开信息采集 → `Phase 2` 预填访谈文档 → `Phase 3` 素材与回复审核 → `Phase 4` 生成六件套 → `Phase 5` 逐文件确认定稿。

## 什么时候用它

- 刚开店 / 刚起号，后面要连着一堆出图和写文案，先把画像立住
- 换季、改定位、上新平台之后回刷档案（不改就一直在按旧色板出图）
- 要写小红书、抖音、公众号三套不同语气的文案，但只有一个品牌底子
- 交给外包装计或外包写手之前，先有一份能发出去执行的规范

## 需要准备什么

| 材料 | 说明 | 必需 |
|---|---|---|
| 品牌 / 账号名称 | 画像目录名用英文小写（如 `my-brand`） | 是 |
| 社媒主页链接或 ID | 小红书 / 抖音 / B站 / 微博 / 公众号，有几个给几个 | 建议 |
| 品牌色 hex 值与字体名 | 第二重要的输入，给不准整套图颜色都不对 | 建议 |
| 3–5 条真实文案原句 | 最重要的输入，让生成内容像「本人」而非通用 AI | 强烈建议 |
| Logo、产品实拍原图 | 高清原图，不要压缩过的截图 | 建议 |

## 操作步骤

### 第 1 步：起个画像名并检查是否重复

告诉它画像名（英文小写，用于目录名）。若 `profiles/<name>/` 已存在，它会先摘要现有内容并问你「更新还是重建」。

### 第 2 步：给公开链接，让它先抓

它用 WebFetch 抓你给的每一个公开页，提取两类东西：

- **可确认的事实**（会标来源）：品牌名、昵称、简介、所在地、品类、粉丝与获赞数、视觉观察（封面风格、滤镜偏好、主色调）
- **抓不到的，全部标成待确认缺口**，不猜

### 第 3 步：拿到一份预填好的访谈文档

它会写一份 `outputs/品牌名/品牌入驻.md`，四部分：

1. **我们已经了解的** —— 让你核对纠正
2. **需要你来回答的** —— 只列真正缺口（ICP、主推产品、最大不同、社媒目标、运营现状）
3. **素材清单** —— 必须项与加分项分开列
4. **品牌与内容细节** —— 排版偏好、标志性格式、3–5 条真实文案原句、内容支柱、绝对不发的内容

### 第 4 步：回填并给素材

填完发回，它会把素材归档到 `assets/logo.png`、`assets/products/`、`assets/lifestyle/`、`assets/examples/`，识别剩余缺口后最多追问 3 个问题。

### 第 5 步：生成六件套并逐文件确认

按 `references/profile-templates.md` 生成六个文件。没拿到的信息写 `[待补充]`，从截图估算的标 `(估算)`——**不编造**。

### 第 6 步：定稿

逐文件确认三件事：有没有事实错误、有没有要删的、有没有要补的。确认后画像生效，包里所有技能自动读取它。

## 你会拿到什么

- `profiles/<name>/` 目录下的六件套档案（`identity.md` / `style.md` / `audience.md` / `platforms.md` / `preferences.md` / `memory.md`）
- `outputs/品牌名/品牌入驻.md` 访谈文档（可反复回填）
- `profiles/<name>/assets/` 素材归档目录
- 一份带来源标注的公开信息摘要，与一份明确标注的缺口清单

## 完整对话案例

### 案例：给一个手工陶瓷店建画像

**你说：** 我刚开了个手工陶瓷杯的店，叫屿陶，先帮我把账号画像建起来。小红书店：yutao_ceramics。

**它做：**

1. 抓小红书公开页，提取到：昵称「屿陶 YUTAO」、简介提到「景德镇自有窑口」、粉丝 1.2 万、封面风格为米白底 + 单只杯特写、主色调偏暖白
2. 生成访谈文档，**第一部分**列出上面这些让你核对；**第二部分**只留 5 个真缺口：ICP、主推产品、和同类最大不同、社媒目标、运营现状

**你回填：** 目标用户是 25–35 岁都市女性、主推 380ml 骨瓷马克杯、和同类不同在于「自有窑口 + 手工描金」、目标是品牌认知 + 带货、目前一周发 3 条图文。

**它产出：**

```
profiles/yutao/
  identity.md     品牌名 屿陶 YUTAO｜定位 手工描金细瓷日用杯
  style.md        语气：克制、讲工艺、不催单
                  视觉：暖白底 #FFF8F4 / 主橙强调色（hex 待确认）
                  文案示例：「描金是手工工序，金线粗细会有细微差异」
  audience.md     25–35 岁都市女性；语言特征：在意「手作痕迹」而非「完美」
  platforms.md    小红书 1.2 万粉｜一周 3 条图文｜主标签 #手作陶瓷 #马克杯
  preferences.md  内容支柱：窑口工艺 / 日常使用场景 / 客户实拍
                  禁区：不宣称检测合格、不写虚构划价
  memory.md       （空模板）
```

**它最后会说：** 画像已保存至 `profiles/yutao/`，包里所有技能将自动读取此画像。其中品牌色 hex 值仍为 `[待补充]`——这项给不准，后面所有出图的颜色都会偏，建议尽快补。

### 案例中的关键差异

同一句需求，**没画像**时它写出的是「品质之选，匠心好杯」这类通用文案；**有画像**时它写出的是「描金是手工工序，金线粗细会有细微差异，属手作痕迹」——这是 `preferences.md` 里那条红线在起作用。

## 常见问题 FAQ

**Q1：它会不会未经允许去爬我的主页？**
A：只抓你在 Phase 1 明确给出的公开链接，且只用一次。不想让它抓，直接把资料贴给它，缺口那几步照常走。

**Q2：`[待补充]` 是不是没做完？**
A：不是，是**保护你**。受众、销量、差异化这些字段如果为了好看硬填，下游引用它们做宣称就是虚假宣传。实测这批字段全是 `[待补充]` 时，交付的详情页照样过合规关卡。

**Q3：品牌色必须给 hex 吗？**
A：第二重要的输入就是它。可以给「近似 #FFF8F4」这种，但估算的必须标 `(估算)`，否则后面所有技能会把估的值当准值用。

**Q4：`memory.md` 为什么是空的？**
A：它不归本技能填，由归因层在后续投放中回写。别指望第一次建档就有历史数据结论。

**Q5：我能自己加第七个文件吗？**
A：不会被读取。它只认六件套这套结构，内容塞到模板之外下游解析不到，等于没写。

**Q6：只想建声音画像怎么办？**
A：SKILL.md 指向 `skill-voice-builder`，但**该技能没有随本包提供**。本包场景请照六件套建全，缺的维度写 `[待补充]`。

## 注意

- **这是纯方法论技能**：只有 `SKILL.md` 和 `references/profile-templates.md`，没有 scripts/，不提供任何命令行，全靠对话推进。
- **它确实会联网抓公开页**（Phase 1 用 WebFetch）。没有可抓的主页、或不想让它抓，就直接把资料贴给它，缺口那几步照常走。
- **`profiles/` 是相对工作目录解析的**，不在技能自己目录下。换工作目录就等于换了一份档案，多个账号请固定在同一个工作目录里操作，或自己把 `profiles/` 备份出来。
- **第六个文件 memory.md 本技能不填**（生成时是空模板），它由归因层在后续投放中回写。别指望第一次建档就有历史数据结论。
- **`[待补充]` 不是没做完，是保护你**。别为了好看让 AI 把受众、销量、差异化补齐——下游引用这些字段做宣称就是虚假宣传。实测这批字段全是 `[待补充]` 时，交付的详情页照样过合规关卡。
- **品牌色值务必给准**。色值是第二重要的输入（第一是文案原句），hex 错了整套图的颜色都不对，估算的必须标 `(估算)`。
- **它只认六件套这套结构**。你手工加第七个文件（比如 `promo.md`）不会被读取；把内容塞进 SKILL.md 的模板之外，下游解析不到就等于没写。
- 只想建声音画像或只做受众画像，SKILL.md 明确指向 skill-voice-builder / skill-audience-profiler，**这两个技能没有随本包提供**；本包场景请照六件套建全，缺的维度写 `[待补充]`。
- **档案要定期回刷**：换季、改定位、上新平台之后不重建画像，后面所有技能仍在按旧色板旧红线出图。
